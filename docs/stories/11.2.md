# Story 11.2: Validated Internal-Link References (Table, Matrix, Inline Run)

Status: Done

## Story

As an author or agent,
I want a typed `linkTo` that points a table row/cell, a comparison-matrix finding, or an inline run at a detail section in the same document,
So that a finding in a table or a phrase in prose drills down to its detail page, with a dangling link caught at validation rather than as a dead click.

## Acceptance Criteria

**Given** a `linkTo: <section-id>` on an inline run (mutually exclusive with the run's external `link.href`), on a table row or cell, and on a comparison-matrix finding
**When** the document is validated
**Then** each `linkTo` parses as a typed internal reference, and a run that carries both `linkTo` and an external `href` is an actionable validation error (a run links internally OR externally, never both) (FR2 parity)

**Given** a `linkTo` whose value matches no section id in the document
**When** the document-level cross-reference pass runs (alongside the existing `scaleRef` / `sourceBlockId` checks)
**Then** validation fails with an actionable problem-details error naming the carrier (the run, the row/cell, or the finding) and the missing target id - no document with a dangling internal link is ever served (FR2 parity)

**Given** a `linkTo` that resolves to an existing section
**When** it is rendered
**Then** it renders as an in-page anchor (`<a href="#<section-id>">`, escaped) - never raw HTML, never a scriptable URL - so renderer purity holds (no `$lib/server`, no `{@html}`)

**Given** an existing document with no `linkTo` anywhere
**When** validated and rendered
**Then** it is unchanged - `linkTo` is additive and optional on every carrier, every existing run / table / matrix unaffected

## Dev Notes

- Authority: `docs/prd/epic-11.md` Epic 11 "Foundational design" (the internal-link reference is a typed `linkTo`, validated against the document, never a raw URL; three carriers; a dangling `linkTo` fails validation in the document-level cross-reference pass like `scaleRef` / `sourceBlockId`; schema additivity) + Story 11.2 AC verbatim above. FR2 parity for both the mutual-exclusion error and the dangling-target error. Architecture: schema is the Zod single source of truth, isomorphic (no `$lib/server` / `$lib/ui` imports in `src/lib/schema`); the renderer is pure (no `$lib/server`, no `{@html}`, escaped, internal anchors only). Scopes touched: `schema` (the `linkTo` fields + refine + cross-ref pass), `render` (the three anchors), `docs` (the published artifact). Builds on 11.1's detail-section `id`s; 11.3 reads the `data-internal-link` anchors for the reveal/back/focus navigation.
- TABLE GRANULARITY (decision): row-level, via a `rowLinks` array PARALLEL to `rows`, NOT a field inside the row record. The row is `z.record(string, tableCell)`, the flat shape ingestion's `resolveTable` fills directly from uploaded data rows; restructuring the row into `{ cells, linkTo }` would ripple through ingestion, rebind, and every row consumer for no authoring gain. A parallel `rowLinks` keeps the row byte-identical (ingestion untouched, an absent `rowLinks` renders identically) and is fully additive. Cell-level linking is NOT clean over the primitive cell model (a cell is a string/number/boolean/null, no metadata slot), so it was not implemented; the epic permits "row-level at least", which this delivers. The anchor renders in the row's FIRST cell.
- MUTUAL EXCLUSION is SECTION-LOCAL (the inline-run `superRefine`), not the document-level pass: both `linkTo` and `link` live on the same run, so the check needs no whole-document context - unlike the dangling-target check, which must resolve `linkTo` against the document's section ids and DOES belong in the document-level pass. Same split 11.1 drew for annex/detail (local) vs a future `linkTo` (document-level).
- CROSS-REF PASS shape mirrors `validateScaleReferences`: a separate isomorphic module (`internal-links.ts`) with structural `*View` types (no block-schema value imported), wired into the one document superRefine in `v1.ts`. Inline-run `linkTo` can live in any paragraph-bearing block (text `paragraphs`, callout `body`, list-item `description`, timeline-milestone `detail`), so the run walk normalizes all four into run arrays; the reported path stops at the rich-text field (enough to locate the block) for list/timeline since the run loop flattens the item nesting.
- INJECTION-SAFETY argument (asserted in tests): `linkTo` is a validated section id (the `idSchema` slug pattern: lowercase letters, digits, single hyphens), so a value carrying a scheme or a URL is REJECTED at the schema before it ever reaches the renderer. The renderer builds the href as the literal `` `#${id}` `` - `#` plus that id only - never accepting an arbitrary URL for `linkTo`, and Svelte attribute interpolation escapes it. So the only href the renderer can emit is a same-document fragment; there is no `javascript:`, no http(s), no protocol surface. Tests assert the href is exactly `#<id>` and matches no `scheme:` prefix.
- DEFERRED TO 11.3 (flagged, not in 11.2 scope): the link-driven reveal/navigation to the detail page, the "back to where you were" affordance, and focus management into the detail page. 11.2 delivers ONLY the correct escaped anchor that works by fragment (the no-JS reader reaches the detail content by anchor, as 11.1 renders detail sections in the DOM); the anchors carry a `data-internal-link` attribute as the stable hook 11.3 binds its reveal JS to. No new reader JS in 11.2 (budget unchanged in kind; 74.0 KB / 200 KB).
- Additivity proof is the load-bearing test (mirror 11.1's no-kind test and 7.1's no-scales test): a document with NO `linkTo` validates AND renders byte-unchanged. No schema-version bump - every field is `optional()`. The published `static/schema/v1.json` gains only the optional `linkTo` (run + finding) and `rowLinks` (table) properties; `required` and the block union are untouched.
