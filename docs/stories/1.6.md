# Story 1.6: The Beautiful Render - Reader Experience Core

Status: Approved

## Story

As a reader,
I want the report as a polished interactive web document,
So that reading it beats opening a slide deck.

## Acceptance Criteria

**Given** a report
**When** opened
**Then** it renders SSR-first in under 1 s (~30 sections), then navigates SPA-style: slide-like sections, in-section scrolling, keyboard and touch (FR3, FR25, NFR1/2)

**Given** the document's links and a section deep-link URL
**When** followed
**Then** internal anchors, external links and direct section access work (FR4, FR26)

**Given** a mobile browser
**When** reading
**Then** the report is fully readable with touch navigation (FR27)

**Given** the default theme (design tokens, AR10)
**When** any report renders
**Then** zero author design work is needed, charts render server-side as SVG (LayerChart, AR11), reader-path JS stays under 200 KB compressed (FR5, NFR3), and axe-core checks pass in e2e (NFR14/15)
**And** the author's workspace preview uses the identical renderer

**Given** the token-structured theme system
**When** a second (test-only) theme definition is applied
**Then** the report renders fully in it with no component change - proving FR39 additivity (AR10)
**And** component and interaction design follows the render tier specification in `ux-design-specification.md`

## Tasks / Subtasks

- [ ] Design tokens in `src/app.css` per UX Visual Foundation (ink/stone/purple palette + semantic colors, type scale Source Serif 4/Inter via Fontsource self-hosted, spacing 4px scale, radii, breakpoints) + a second test-only theme proving swap
- [ ] `src/lib/render/` tier: Report (slide/scroll modes), SectionSlide (viewport card, in-card scroll, annex variant), Toc (one-key overlay), ProgressRail, and the five blocks - TextBlock, TableBlock (sticky header, tabular figures), ChartBlock (LayerChart SSR SVG), KpiBlock, ImageBlock (required alt)
- [ ] Navigation: arrows/PageUp-Down keyboard, touch swipe/edge-tap, scroll within section; `t` TOC, `f` fullscreen; section deep links (stable fragments); `prefers-reduced-motion` respected
- [ ] Workspace preview route `[id]/preview` consuming the identical renderer (LivePreview)
- [ ] Performance: verify reader-path JS < 200 KB compressed (build analysis); SSR render timing on a ~30-section fixture; record numbers in Dev Agent Record
- [ ] Accessibility: semantic structure (sections -> headings), focus visibility, contrast pairs as unit-tested token assertions; axe-core wired into Playwright e2e and CI
- [ ] e2e: reader navigation happy path (desktop + mobile viewport), deep link, keyboard-only pass

## Dev Notes

- THE differentiator story. Authority: UX spec in full (Visual Design Foundation, Design Direction "Modern Gazette", render-tier component table, Responsive & Accessibility); architecture D11/D12/D13 and NFR1/2/3.
- LayerChart: measure hydration cost against the budget; architecture's stated fallback is SSR-only SVG (zero hydration) if it busts 200 KB - decide by measurement, record the decision.
- Fonts via Fontsource packages (self-hosted files end up in the build, no external requests - CSP rule).
- Charts must not ship raw datasets client-side beyond what the SVG needs (NFR3).
- This story owns app.css tokens; if 1.5 introduced a minimal slice, consolidate here.
- Renderer purity: components consume validated document + tokens only - no fetch, no service imports.
