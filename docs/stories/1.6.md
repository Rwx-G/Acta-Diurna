# Story 1.6: The Beautiful Render - Reader Experience Core

Status: Review

## Story

As a reader,
I want the report as a polished interactive web document,
So that reading it beats opening a slide deck.

## Acceptance Criteria

**Given** a report
**When** opened
**Then** it renders SSR-first in under 1 s (~30 sections), then navigates SPA-style: slide-like sections, in-section scrolling, keyboard and touch (FR3, FR25, NFR1/2)

**Given** the document's links and a section deep-link URL
**When** followed
**Then** internal anchors, external links and direct section access work (FR4, FR26)

**Given** a mobile browser
**When** reading
**Then** the report is fully readable with touch navigation (FR27)

**Given** the default theme (design tokens, AR10)
**When** any report renders
**Then** zero author design work is needed, charts render server-side as SVG (LayerChart, AR11), reader-path JS stays under 200 KB compressed (FR5, NFR3), and axe-core checks pass in e2e (NFR14/15)
**And** the author's workspace preview uses the identical renderer

**Given** the token-structured theme system
**When** a second (test-only) theme definition is applied
**Then** the report renders fully in it with no component change - proving FR39 additivity (AR10)
**And** component and interaction design follows the render tier specification in `ux-design-specification.md`

## Dev Notes

- THE differentiator story. Authority: UX spec in full (Visual Design Foundation, Design Direction "Modern Gazette", render-tier component table, Responsive & Accessibility); architecture D11/D12/D13 and NFR1/2/3.
- LayerChart: measure hydration cost against the budget; architecture's stated fallback is SSR-only SVG (zero hydration) if it busts 200 KB - decide by measurement, record the decision.
- Fonts via Fontsource packages (self-hosted files end up in the build, no external requests - CSP rule).
- Charts must not ship raw datasets client-side beyond what the SVG needs (NFR3).
- This story owns app.css tokens; if 1.5 introduced a minimal slice, consolidate here.
- Renderer purity: components consume validated document + tokens only - no fetch, no service imports.

## Dev Agent Record

### Debug Log

- **Dependencies (exact-pinned):** `layerchart 1.0.13`, `d3-scale 4.0.2`, `d3-shape 3.2.0`, `@fontsource/source-serif-4 5.2.9`, `@fontsource/inter 5.2.8`, `@fontsource/cinzel 5.2.8` (runtime); `@types/d3-scale 4.0.9`, `@types/d3-shape 3.1.8`, `@axe-core/playwright 4.11.3`, `testcontainers 12.0.1`, `@testcontainers/postgresql 12.0.1` (dev).
- **LayerChart SSR / chart hydration decision:** LayerChart 1.x is a heavy component framework (layercake, dagre, d3-geo/sankey, lodash-es, date-fns, @layerstack/tailwind; ~600 KB unpacked) whose components require client hydration to mount the LayerCake context. Shipping it to the reader would bust the 200 KB budget and contradict NFR3 (no raw datasets client-side). **Decision: ChartBlock renders SSR-only as static SVG, zero hydration** - the architecture's stated D12 fallback, chosen by measurement. Geometry (line/bar/area/pie) is computed with `d3-scale` + `d3-shape` (pure math, no DOM) in `chart-geometry.ts`; the SVG carries only paths/ticks, never the source values. Verified: **zero d3/layerchart code in the entire client build** (`grep` of `.svelte-kit/output/client` for `layercake|d3-sankey|scaleLinear` returns nothing). `layerchart` stays a declared dependency per AR11/D12; its d3 modules are its own transitive deps, used here as the honest minimal footprint of the SSR fallback.
- **Reader-path JS budget (NFR3):** `scripts/reader-bundle-size.ts` (`pnpm reader:budget`) walks the built client manifest from the view-route node (node 8, a `+page@.svelte` that resets to the root layout node 0 - it does not pull the workspace layout), sums the gzipped static-import closure: **62.3 KB, well under 200 KB**. The view-page node itself is 0.3 KB; the bulk is the Svelte 5 runtime + SvelteKit client.
- **SSR timing (NFR1):** `ssr-performance.test.ts` renders a 30-section / 90-block / 30-chart fixture via `svelte/server` `render()`: complete HTML (all sections, every chart as inline SVG, no canvas), **sub-millisecond per render** (asserted < 250 ms with two orders of magnitude headroom). Far under the 1 s budget.
- **Fonts self-hosted (CSP):** Fontsource per-weight CSS imported via `src/lib/fonts.css` (`@import`), Vite bundles the woff2 into the build. Verified: **no external font/http/cdn URLs in the built CSS**; 41 woff2 files copied to `_app/immutable/assets` (latin + latin-ext + cyrillic/greek/vietnamese subsets; the browser loads only the needed ranges via `unicode-range`). Strict CSP added inline in `vite.config.ts` (`default-src 'self'`, no third-party origins; `style-src` keeps `unsafe-inline` for Svelte scoped styles and SSR inline `style` attributes - no `unsafe-eval`, no external origins).
- **Contrast (NFR14/15):** `contrast.ts` + 17 unit tests assert report-content pairs hold AAA (7:1) and text-on-accent holds the AA floor, for both built-in themes. The midnight theme's brand on-dark purple (`#a8326e`) is only 2.93:1 as text, so the text accent is lightened to `#e090b8` (7.75:1) while the vivid purple stays for decorative fills (`--report-accent-fill`).
- **axe-core gate caught two real a11y bugs:** (1) ImageBlock placeholder asset-id label at `opacity:0.7` computed to 3.74:1 - fixed to full `--report-text-muted`; (2) slide-mode section cards are scroll containers needing keyboard access - added `tabindex=0` (axe `scrollable-region-focusable`). After fixes, **axe clean (WCAG 2 A/AA) on the report and the TOC overlay, desktop + mobile**.
- **e2e harness (ran locally against Docker 29.5.2):** `globalSetup` starts a Postgres testcontainer, migrates, seeds the fixture report (the schema full example, fixed id), spawns `node build` against it, waits for `/healthz`, and returns a teardown stopping both. A `setup` project authenticates once into storage state (one login keeps the suite under the AR12 login rate-limit; signing in per test tripped the 5-burst bucket). **15 checks pass** (2 setup + reader navigation/keyboard/TOC/deep-link + axe, across desktop + mobile/Pixel 7).
- **Login-over-HTTP CSRF gotcha (note for reader stories / Epic 3):** over plain HTTP the app's `Referrer-Policy: no-referrer` makes Chrome send `Origin: null` on a form POST, which trips SvelteKit's CSRF origin check ("Cross-site POST form submissions are forbidden"). Production serves over HTTPS where the real Origin is sent and the form works; the e2e auth helper posts login through the request API with an explicit Origin as an HTTP-only test concession. Worth confirming the reader magic-link form behaves under the deployed HTTPS in Epic 3.
- **Gates (final):** `pnpm lint` exit 0; `pnpm check` 889 files, 0 errors / 0 warnings; `pnpm test` 245 unit tests passed (34 files); `pnpm build` adapter-node done; e2e 15 passed.

### Completion Notes

- **Tokens (`src/app.css`)**: consolidated the partial 1.4/1.5 slice into the full Visual Design Foundation - brand palette + ink-opacity variants + desaturated workspace semantics, 1.250 modular type scale (pre-computed for cross-browser stability), 4px spacing, radii, focus-ring tokens, documented breakpoint constants. Semantic `--report-*` tokens are the single theme surface: renderers reference only those, never the raw palette. **FR39 proven**: the `midnight` theme is a `[data-theme='midnight']` override block of only the `--report-*` tokens; a report re-skins with zero component change (asserted in `Report.svelte.test.ts` and the contrast tests).
- **Renderer purity**: every `src/lib/render/` module consumes a validated/preview document + theme tokens only; the ESLint render-boundary guard stays green. `document-view.ts` has two entry points: `toReportView` (reader, validated document) and `toPreviewView` (workspace, tolerates a transiently-invalid snapshot - validates each block in isolation so valid blocks render and invalid ones show a per-block notice instead of throwing).
- **ChartBlock**: SSR-only SVG (see Debug Log). `KpiBlock` trend uses a glyph + `sr-only` label so meaning is never color-alone. `TextBlock` renders inline runs through Svelte text interpolation (escaped, never `{@html}`); links carry `rel="external noopener noreferrer"` + `target="_blank"` (the `external` token also satisfies the SvelteKit no-navigation-without-resolve lint for outbound URLs). `ImageBlock` renders the required alt + a placeholder frame keyed by `assetId` (uploads arrive Epic 2).
- **Navigation** (`Report.svelte` + `navigation.svelte.ts`, a Svelte 5 rune store per D11): keyboard (arrows/PageUp-Down/Home/End/Space), touch swipe + edge-tap, `t` TOC, `f` fullscreen, deep links via `#<sectionId>` (resolved on load, kept in sync via IntersectionObserver + `history.replaceState`), `prefers-reduced-motion` makes transitions instant and keeps chrome from fading. Slide mode falls back to scroll on narrow/short viewports. SSR-complete then hydrates only for SPA navigation.
- **Reader route** `(workspace)/reports/[id]/view/+page@.svelte`: author-only preview-by-id under the workspace guard (the hook-level `workspaceGuard` covers it; the `+page@` reset is for a full-bleed reader, not an auth bypass). The public magic-link reader `/r/[token]` is left for Epic 3 - not built here.
- **Workspace preview** `[id]/preview`: `LivePreview.svelte` embeds the identical `Report` (embedded mode, no fixed chrome) fed the stored document through the tolerant preview path, with a desktop/mobile viewport toggle. The editor toolbar links to both `/preview` and `/view`.
- **For 1.7 (publish lifecycle):** the render path is the same for draft and published documents - the view/preview routes already render any report by id. When 1.7 adds the publish action, the **version dispatch point** is `validateDocument` -> `getSchema(version)` in the schema package (1.2), which the render path consumes transitively via the stored `DocumentV1`. The render tier needs **no change** for publish: it renders whatever validated document the lifecycle persists. The natural hook is (a) gating `/view` (and the future `/r/[token]`) on `status === 'published'` once publishing exists, and (b) snapshotting the document at publish time so the reader sees a frozen version while the draft keeps evolving. The reader render itself is version-agnostic: it consumes the output-side `DocumentV1` the schema already normalizes (defaults applied), so N/N-1 compatibility (FR7) lives entirely in the schema layer, not the renderer.

### QA iteration 1 (2026-06-12)

Fixes applied against the QA gate findings:

- **[Critical] KPI trend tokens AA on midnight.** Trend up/down no longer use the workspace-chrome `--color-green`/`--color-danger` (which are never report content and fell below AA on the midnight ground). New semantic `--report-trend-up`/`--report-trend-down` tokens live in the theme surface: light `#2f6b4a` (5.61:1) / `#a23b3b` (5.78:1) on stone, midnight `#6fbf95` (8.37:1) / `#f08a8a` (7.62:1) on `#14131f`. Mirrored in `palette.ts`; contrast tests now assert both trend tokens hold the AA floor on both themes.
- **[High] noindex / NFR10 baseline.** `<meta name="robots" content="noindex, nofollow">` on the reader view and the workspace preview heads; `X-Robots-Tag: noindex, nofollow` added by the `securityHeaders` hook for `/reports/*/view`, `/reports/*/preview` and the future `/r/*` reader; `static/robots.txt` now disallows `/r/` and `/reports/`.
- **[High] frameInvalid heuristic.** Re-derived from the section validation result (`!sectionResult.success && blocks.every(b => b.block !== null)`) instead of the block-array state, so an empty-blocks bad-title section flags as a frame problem and an all-invalid-blocks section does not (blocks carry their own notices). Two regression tests added.
- **[High] Reader JS budget CI gate.** `pnpm reader:budget` now runs after `pnpm build` in the `build` CI job. The script was hardened first: it resolves the view-route and root-layout nodes by their `+page@.svelte`/`+layout.svelte` source (read from the generated `client-optimized/nodes`) instead of hardcoded indices 8/0, so adding routes cannot point the budget at the wrong chunk. Still reports 62.3 KB.
- **[High] Dropped the phantom `layerchart` dependency.** It shipped zero runtime code (charts use d3-scale/d3-shape directly, both already direct deps); removed from `package.json`, lockfile updated (88 packages pruned), no `layerchart` import remains in `src`. The SSR d3 fallback supersedes the dep; re-add only if the deferred `renderChart()` PDF-export path is built.
- **[Medium] Placeholder dedup.** Extracted `BlockPlaceholder.svelte` (optional `message` prop) used by ChartBlock/KpiBlock/TableBlock; removed the triplicated CSS. ImageBlock's figure-style placeholder stays distinct (aspect-ratio frame + alt).
- **[Medium] Toc scrim token.** New `--report-scrim` (light: ink veil; midnight: light-text wash, since an ink veil is invisible on the dark page); Toc no longer hardcodes `--color-ink`.
- **[Medium] chart-geometry edge cases.** Added single-point line/area (well-formed, NaN-free paths), negative-value bar (height >= 0, bars straddle the zero line), all-zero pie (no NaN/undefined slices).
- **[Low] Token cleanups.** ChartBlock tick/slice-label `12px` -> new `--text-tick` token; preview `h1` `20px` -> `var(--text-lg)`; removed the superseded `ssr-timing.test.ts` (ssr-performance covers SSR); `// test-only` comment on the e2e `SESSION_SECRET`.
- **[Minor, 1.5 leak] binding warnings.** Edit-tier `*.svelte.test.ts` blocks now wrap their prop in `$state(...)` so the `block = $bindable()` target is reactive; `binding_property_non_reactive` no longer appears in test logs.
- **Gates after iter 1:** `pnpm lint` exit 0; `pnpm check` 889 files / 0 errors / 0 warnings; `pnpm test` 253 unit tests (33 files); `pnpm build` clean; `pnpm reader:budget` 62.3 KB; `pnpm test:e2e` 15 passed (axe-core clean on desktop + mobile after the token changes).
