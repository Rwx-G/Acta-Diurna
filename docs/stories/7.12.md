# Story 7.12: Field-Grid Meta-Strip Variant

**Epic:** 7 (Report Brick Library, Phase B)
**Status:** Done

## Story

As an author,
I want a horizontal centred meta-strip layout for the field grid,
So that a report header can show Author / Date / Scope / Status as a single divided row under the title.

## Acceptance Criteria

**Given** an existing `field-grid` block with a `layout` of `strip` (vs the default grid)
**When** rendered
**Then** the same `{ label, value }` items render as a horizontal, centred row of label-over-value cells separated by dividers, collapsing gracefully at the reader mobile breakpoint

**Given** a `field-grid` with no `layout` (or `layout: grid`)
**When** validated and rendered
**Then** it renders exactly as today - the `layout` field is additive and optional, every existing field-grid unchanged

**Given** the variant
**When** audited
**Then** it is SSR, Zod-validated, renderer-pure, AAA on the default theme, within the reader budget

## Dev Notes

- This is the smallest Phase B brick: a layout VARIANT on the existing 7.3 field-grid, NOT a new block. There is no new union member, so `json-schema.test.ts` (union size), `errors.test.ts` (block-type hint), and `StructureTree.svelte` (block-summary switch) need NO change and stay green untouched.
- Additivity is enforced at the renderer level by NOT emitting the `layout-grid` class on the default path: the `<dl>` keeps exactly `class="field-grid"` (no extra token) when `layout` is absent or `grid`, so the grid render is byte-identical to the pre-7.12 component (asserted by comparing `outerHTML` of the default vs explicit-`grid` render). The strip styling is purely additive: a `.field-grid.strip` selector overrides the grid display to a centred flex row and the dividers are `::before` pseudo-elements between adjacent `.field` cells.
- The dividers are pure CSS (`::before` on `.field + .field`), so they add no markup and no client JS; at the 768px breakpoint the strip becomes `flex-direction: column` and the dividers are dropped (`content: none`), matching the grid's mobile collapse. Zero hydration, reader budget unchanged.
- The editor deletes `block.layout` when the author picks `grid` rather than writing `layout: 'grid'`: the default is implicit, so a document only ever carries `layout` when it is `strip`. This keeps existing documents and grid-authored documents free of a redundant field and mirrors the optional-field-delete pattern the list/card editors use for empty optional values.
- The reference look is the correlation report's centred meta-strip under the title (Author / Date / Scope / Status as one divided row). The same `{ label, value }` items and the same `<dl>/<dt>/<dd>` semantics serve both layouts; only the CSS differs.
- AAA: the strip reuses the exact `--report-text` / `--report-text-muted` token pairing the grid already passes axe-core with; the divider uses the decorative `--report-rule` token (a hairline, not prose), so no new contrast surface is introduced.
