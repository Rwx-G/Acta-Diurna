# Story 2.2: Save Skeletons & Instantiate Reports

Status: Approved

## Story

As the author,
I want to save a skeleton and create new reports from it,
So that every issue of a recurring report has an identical structure.

## Acceptance Criteria

**Given** an assembled structure
**When** I save it as a named skeleton
**Then** it is stored (skeletons table - created by this story's migration) and listed in my skeleton library (FR9)

**Given** a skeleton name already in use
**When** saved
**Then** a problem-details error asks for a distinct name

**Given** a saved skeleton
**When** I create a report from it
**Then** the report's sections, blocks, and bindings mirror the skeleton exactly (FR11)

**Given** two reports created from the same skeleton
**When** compared
**Then** their structures are identical (automated structural equality test)

## Tasks / Subtasks

- [ ] skeletons table migration (id uuidv7, name text unique, document jsonb (the structure), schema_version int, created_at/updated_at timestamptz)
- [ ] `src/lib/server/skeletons/` service: saveSkeleton(name, structure) -> validate + store (409 /problems/skeleton-name-taken on duplicate name), listSkeletons, getSkeleton, deleteSkeleton; instantiateReport(skeletonId) -> creates a draft report whose document mirrors the skeleton's structure exactly (reuse documents service createReport path with the skeleton document instead of the seed)
- [ ] Workspace routes: skeleton library list (the left-rail "Skeletons" link, enabled now), save-skeleton action from the composer (2.1), "Create report from skeleton" action
- [ ] Structural equality: a pure helper comparing two documents' structure (sections/blocks/bindings, ignoring ids and content values); tested that two instantiations from one skeleton are structurally identical
- [ ] Tests: save (valid, duplicate-name 409), list, instantiate mirrors structure, structural-equality of two instantiations (FR11), delete

## Dev Notes

- Authority: architecture (services own Drizzle, JSONB storage like reports), FR9/FR11. Reuse the documents service instantiation path - a report from a skeleton is createReport seeded with the skeleton document.
- The skeleton document is a DocumentV1 structure with placeholder bindings (from 2.1). Instantiation copies structure + bindings; new uuidv7 block/section ids may be regenerated OR preserved - structural equality must hold either way (compare by position/shape, not id). Document the choice.
- "Skeletons" left-rail link was disabled in 1.5; enable it here.
- Structural-equality helper is reused by the FR11 test and is generally useful - place in skeletons service or a shared util.
