# Story 2.4: Upload Data Files & Bind Blocks

Status: Approved

## Story

As the author,
I want to upload data files and bind their contents to report blocks,
So that my exported tool data becomes charts and tables without manual re-entry.

## Acceptance Criteria

**Given** a CSV, JSON, or Excel file up to 50 MB
**When** uploaded
**Then** it is parsed and stored (uploads volume + data_sets table - created by this story's migration, carrying the injection timestamp and an optional data-as-of field), and its fields/columns are inspectable, with visible progress (FR12, NFR4, FR16 groundwork)

**Given** a parsed data set
**When** I bind a table/chart/KPI block to its fields
**Then** the block renders the bound data and the binding persists in the document

**Given** an unparseable file
**When** uploaded
**Then** a problem-details error states what failed (encoding, format, size) - never a silent failure

## Tasks / Subtasks

- [ ] data_sets table migration (id uuidv7, report_id fk nullable (or skeleton scope), filename, source_format, fields jsonb (inspected columns+types), injected_at timestamptz, data_as_of timestamptz nullable (FR16 groundwork), storage_path text)
- [ ] `src/lib/server/ingestion/` service: parsers for CSV / JSON / Excel; size cap 50 MB enforced BEFORE full parse (NFR4 + the 1.5 body-size backlog item - reject oversize with 413); field/column inspection (name + inferred type string/number/date/boolean); store the file on the uploads volume (UPLOADS_DIR), metadata in data_sets; parse failures -> problem-details (encoding/format/size, never silent)
- [ ] Binding resolution: given a data_set and a block binding (binding.fields), map fields onto the block's render slots (table columns, chart series x/y, kpi items) and produce the bound static data the renderer consumes. DECISION (per backlog/architect rec): the binding declares per-field target slot mapping; document the exact mapping contract here as the canonical reference Epic 2.5 + future stories use. Keep it schema-additive (no breaking change to schema v1 - extend binding shape additively if needed, bump only if unavoidable and document).
- [ ] Workspace: upload UI (FileDrop with visible progress per UX), data-set inspector (fields list), bind action on table/chart/kpi blocks in the editor
- [ ] Dependency: a maintained Excel parser (e.g. exceljs or a lighter xlsx reader) - exact-pinned, justify in Completion Notes; CSV/JSON via stdlib/light parser. Verify license Apache-compatible.
- [ ] Tests: parse CSV/JSON/Excel (fixtures), size-cap rejection, unparseable-file diagnostics, field inspection types, binding resolution maps fields to slots and renders, binding persists in document

## Dev Notes

- Authority: FR12/FR14/FR15 groundwork, NFR4, architecture (ingestion domain under server/, diagnostics first-class). The binding-to-slot mapping is the decision flagged in docs/backlog.md - resolve it here per the architect recommendation (additive, per-field target slot) and make this story's Completion Notes the canonical contract for 2.5.
- New dependency for Excel parsing is expected and pre-approved in spirit by the architecture (CSV/JSON/Excel ingestion named in PRD FR12); pick the lightest maintained option, exact-pin, Apache-compatible license, and record it.
- Uploads volume: UPLOADS_DIR env exists from 1.3 compose. No remote URLs (CSP/no-phone-home). Asset storage is local files referenced by data_sets rows.
- FR16 (data-as-of timestamps, P2/Epic 6) groundwork: data_sets carries injected_at + optional data_as_of now; rendering the timestamp is Epic 6.
- Size cap must be enforced before buffering the whole file (stream or check content-length + cap) to honor the DoS concern from 1.2/1.5 backlog.
