# Story 1.5: Create & Edit a Structured Report

Status: Approved

## Story

As the author,
I want to create a report and edit its typed blocks with immediate validation feedback,
So that I can build a complete document without fighting the tool.

## Acceptance Criteria

**Given** the workspace
**When** I create a report
**Then** a draft is stored (reports table, JSONB document, schema v1) (FR1, FR6)

**Given** the editor
**When** I add, edit, remove, or reorder sections and blocks of the five types
**Then** changes persist and re-validate on save

**Given** an invalid edit
**When** saved
**Then** the actionable error (block, field, hint) is displayed at the failing block - never a silent failure (FR2)

## Tasks / Subtasks

- [ ] reports table migration (id, title, status draft/published, schema_version, document JSONB, timestamps)
- [ ] `src/lib/server/documents/` service: create/get/list/update (validate-on-write via schema package, AppError with errors[] on failure), delete draft
- [ ] Workspace routes: reports list (left rail layout per UX), new report, `[id]/edit` editor
- [ ] Block editor (UI tier): ordered sections with inline title edit, add/remove/reorder blocks of the five types, per-block edit forms, autosave debounced with quiet "saved" timestamp (UX patterns: forms, morphing CTA groundwork)
- [ ] Inline validation rendering: errors[] mapped to the failing block/field in the editor (UX "errors are guidance")
- [ ] Tests: document service CRUD + validation errors (Vitest); create-edit-save e2e happy path + invalid edit path (Playwright)

## Dev Notes

- Authority: architecture patterns (routes thin, services own Drizzle, form actions with progressive enhancement), D2 (JSONB), UX spec (StructureTree-like editing, BlockInspector simplified - full composer UX arrives with skeletons in 2.1; here a clean ordered editor is enough), known accepted gap: MVP editor is structured, not WYSIWYG.
- The editor reuses the schema package types end to end - no duplicated shapes.
- Data-bound blocks (table/chart/kpi) at this stage: support inline static data authoring (binding to uploads arrives in Epic 2); binding declarations editable as named expected fields.
- Block forms consume UI primitives built on tokens (app.css tokens land in 1.6 - if 1.5 runs first, introduce the minimal token slice needed and let 1.6 complete it; coordinate via File List).
