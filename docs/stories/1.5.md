# Story 1.5: Create & Edit a Structured Report

Status: Done

## Story

As the author,
I want to create a report and edit its typed blocks with immediate validation feedback,
So that I can build a complete document without fighting the tool.

## Acceptance Criteria

**Given** the workspace
**When** I create a report
**Then** a draft is stored (reports table, JSONB document, schema v1) (FR1, FR6)

**Given** the editor
**When** I add, edit, remove, or reorder sections and blocks of the five types
**Then** changes persist and re-validate on save

**Given** an invalid edit
**When** saved
**Then** the actionable error (block, field, hint) is displayed at the failing block - never a silent failure (FR2)

### Completion Notes

- **reports table (D2)**: JSONB `document` is the source of truth; `title` and `schema_version` are mirrored relational columns so lists and version queries never parse JSONB. Status is a text check constraint (draft|published), default draft. Ids UUIDv7 app-side.
- **documents service** (`src/lib/server/documents/reports.ts`): owns all Drizzle access. `createReport(title)` seeds one section ("Introduction") holding one text paragraph written as an authoring prompt ("Introduce the report here: what period it covers..."), validated through `validateDocument` like every write. `getReport`/`listReports` (id/title/status/updatedAt, updated desc), `updateReportDocument` (validate-on-write; mirrors document title + version onto the row), `updateReportTitle` (rewrites `document.title` and goes through the same document path - single source of truth), `deleteDraft`. Errors: 422 AppError built from `toProblemDetails` (type `/problems/document-validation`, `errors[]` passthrough), 409 `/problems/report-published` for any write/delete on a published report, 404 for unknown or malformed ids (boundary check avoids postgres uuid cast errors).
- **Routes**: `(workspace)/+layout.svelte` is the left-rail shell (Reports link via `resolve()`, Skeletons/Settings disabled spans, sign-out posting relative `?/logout` - every workspace page exposes the shared logout action). `/reports` lists with EmptyState ("No reports yet - create your first") and per-draft delete with the UX inline-confirm swap (5 s, enhance-cancelled first click; no-JS deletes directly). `/reports/new` has a redirecting GET load and a default POST action creating "Untitled report" then 303 to the editor. `/reports/[id]/edit` load translates service AppErrors via `error(status, errorPageShape(e))` because handleError cannot set non-500 statuses (1.4 note).
- **Autosave choice (documented)**: one real form action (`?/save`) with a visible Save button as the no-JS baseline; with JS every edit debounces 800 ms then `requestSubmit()`, so autosave and manual save share one `use:enhance` path. The enhance callback injects `JSON.stringify($state.snapshot(doc))` as the `document` field and applies the result WITHOUT `update()` (a data reload would clobber in-flight edits); a save in flight defers and reschedules; `beforeunload` guards the dirty window. Quiet "Saved at HH:MM UTC" from the action's `savedAt`.
- **Progressive enhancement scope**: the no-JS save path applies the named narrative fields (`title`, `section-title:<si>`, `paragraph:<si>:<bi>:<pi>`) onto the stored document server-side (`applyNarrativeFields`), then validates. Structural ops and data-block fields require JS - accepted MVP gap, consistent with the desktop-only workspace.
- **Inline validation (FR2)**: a 422 returns `errors[]`; `groupErrorsByLocation` maps index-based paths against the SUBMITTED document snapshot to stable section/block ids, so each error renders inside the failing block card (message + hint + field path, `role="alert"`) even if the author reorders before fixing; section-level errors render at the section, everything else in a document-level panel. Never toast-only.
- **Editor structure** (for 1.6 and 2.1): `ReportEditor.svelte` (state owner, save form, keyed remount per report id) > `SectionEditor.svelte` (title, move/remove, add-block row, audiences) > `BlockEditor.svelte` (one file, five type branches narrowed via `{@const}`) + `AudiencePicker`/`BindingEditor` (bind the precise field, not the whole block - Svelte 5 ownership validation requires bound props for child mutation). Pure helpers in `editor-state.ts` (block factories, moveItem, error grouping, narrative application).
- **Editing model the renderer (1.6) will consume**: documents written by this editor contain text paragraphs as single plain runs (`[{text}]`) - editing a paragraph flattens its runs (`paragraphText` concatenation), untouched paragraphs keep agent-authored formatting; table cells authored as strings (schema cell union unchanged); kpi values authored as strings; optional fields are omitted, never `[]`/`''` (audiences, unit, trend, caption, rows/series/items deleted when emptied); new-block starters: text/table/chart schema-valid immediately, kpi/image intentionally start invalid so validation names the empty fields (errors are guidance); image assetId input disabled with the "uploads arrive with data injection (Epic 2)" note, existing ids preserved.
- **Published reports**: editor renders read-only (whole form in `<fieldset disabled>`, note shown); service refuses writes with 409 as defense in depth. The publish action itself is story 1.7.
- **UI primitives** (`src/lib/ui/`): Button (primary purple filled / secondary outline / danger text; `type` defaults to "button" so structural buttons inside the save form never submit), StatusChip (draft/published, green token family added in app.css with pill radius and danger/purple tints), EmptyState (title/description/action snippet). All token-based, typed props.
- **For 1.6**: `load` returns the full `Report` (document is `DocumentV1`, output side with defaults applied - `table.options.stickyHeader` present when options exist); list timestamps render with the deterministic `YYYY-MM-DD HH:MM UTC` format to avoid SSR/CSR locale drift - reuse or replace consciously. The `--color-green`/`--radius-pill`/tint tokens extended app.css per the 1.5/1.6 coordination note.

### QA iteration 1 (all findings applied)

1. **(Critical - auth bypass) Workspace actions ran with no auth.** The `(workspace)` layout `load` only guards GET page loads; it never runs for form actions or `+server` endpoints, so a POST to `?/save`, `?/delete`, or `/reports/new` reached the action with no session. Fixed centrally with a `workspaceGuard` handle in `src/hooks.server.ts`, placed AFTER `authorRealm` (it reads `locals.authorSession`) and added to the `sequence`. It short-circuits BEFORE `resolve()` - and therefore before any action or endpoint runs - for every author-realm request with no session: page form posts and GETs get a 303 to `/login`, `/api/*` mutations get a 401 `application/problem+json` (`/problems/unauthenticated`). A central `isPublicPath` predicate lists the only non-author paths (`/login`, `/healthz`, `/r/...` reader routes for Epic 3, SvelteKit asset namespaces, favicon/robots). The layout guard stays for defense in depth. Tests (`src/hooks.server.test.ts`): unauthenticated POST to create/save/delete redirects to /login and `resolve` is never called (no DB write); GET also guarded; `/api` mutation returns 401 problem+json; public paths pass through; authenticated author reaches the action. Verified live in compose: with NO cookie, POST to all three endpoints returned `{"type":"redirect","status":303,"location":"/login"}` (the guard target, not the action's redirect) and the reports table stayed at 0 rows; with the cookie, POST /reports/new ran the action, redirected to `/reports/<uuidv7>/edit`, and the row count went to 1.
2. **(High) No-JS save 404 graceful.** The no-JS `getReport(params.id)` in the save action already sits inside the action try/catch, so a report deleted between load and submit surfaces as a mapped 404 failure, never a 500; added a regression test asserting the 404 path returns a graceful failure without calling `updateReportDocument`.
3. **(High) `submittedDoc` reactivity.** `submittedDoc` in `ReportEditor.svelte` was a plain `let`, so the `$derived` error mapping captured the initial null and never re-grouped after a save reassigned it. Now `$state<DocumentV1 | null>(null)`, so the error-to-block mapping recomputes against the submitted (rejected) document after each save.
4. **(High) BlockEditor split.** The five-type monolith became a thin dispatcher keeping the shared header/issue/audience chrome; the type-specific bodies moved to `TextBlockEditor`, `TableBlockEditor`, `ChartBlockEditor`, `KpiBlockEditor`, `ImageBlockEditor`, each carrying its own helpers (`renameColumnKey`/`removeColumn`, `setKpiTrend`, the chart y finite-guard). Behavior identical. New branch tests (`block-type-editors.svelte.test.ts`): table column rename migrates row values, kpi trend clears to delete the field, chart y stays finite (0) when cleared.
5. **(Med) Optimistic concurrency.** `updateReportDocument` gained an optional `expectedUpdatedAt?: Date`; when given it joins the WHERE (`and(eq(id), eq(updatedAt))`) and a zero-row update raises 409 `/problems/report-conflict`. 1.5 stays single-writer (omits it); Epic 4 opts in. `updateReportTitle` and `updateReportDocument` now share one `writeDocument` helper, reading the row exactly once per write. Tests cover the match path, the stale-conflict 409, and the untouched row on conflict.
6. **(Med) Explicit error-to-document mapping.** The save action returns the submitted document and the page maps errors against THAT snapshot, not the live doc. Added a `groupErrorsByLocation` test reordering sections between submit and render, asserting the error stays on the right block id.
7. **(Med) Shared `IssueList.svelte`.** Extracted the triplicated issue markup (document/section/block) into one component with a `variant`; consumed by `ReportEditor`, `SectionEditor`, `BlockEditor`.
8. **(Med) `formatUtcTime` / `formatUtcDateTime`.** Moved the magic slice offsets into `src/lib/format.ts`; the editor's "Saved at" label and the reports-list timestamp reuse it (no more duplicated `slice(11, 16)`).
9. **(Med) Readable field labels.** The raw `<code>{issue.path}</code>` is replaced by `humanizePath(path)` (strips indices, splits camelCase) in `IssueList`, so the author sees `alt`, not `sections[0].blocks[0].alt`.
10. **(Low) Honest splice mutations.** Remove buttons only render inside `{#each items ?? []}`, so the items provably exist; the defensive `?.` on the splice mutations (table rows, chart series, kpi items) was removed in favor of `!` (no handling of impossible scenarios).
11. **(Low) `StatusChip` imports `ReportStatus`** (type-only) from the documents service instead of an inline `'draft' | 'published'` literal.
12. **(Low) `DEFAULT_REPORT_TITLE`** extracted to `reports/new/constants.ts` (SvelteKit forbids arbitrary exports from `+page.server.ts`) and consumed by the action and its test.
13. **(Low) editor-state id comment** rewritten to clarify slug-vs-uuid: editor section/block ids only need to satisfy the schema slug rule and are document-internal anchors, never row primary keys (those are server-assigned UUIDv7).
