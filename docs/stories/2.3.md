# Story 2.3: Duplicate a Previous Issue

Status: Review

## Story

As the author,
I want to duplicate an existing report to start the next issue,
So that the fastest path to this week's report is last week's.

## Acceptance Criteria

**Given** any report
**When** I duplicate it
**Then** a new draft is created with identical structure and bindings, cleared share links, and a draft status regardless of the source's status (FR10)

## Tasks / Subtasks

- [x] `duplicateReport(id)` in the documents service: creates a new draft report (uuidv7) copying the source document (structure + bindings + content), status forced to draft regardless of source, published_document/published_at cleared, share links not carried (shares arrive Epic 3 - ensure the duplicate has none)
- [x] Workspace: "Duplicate" action on the reports list and/or editor, redirect to the new draft's editor
- [x] Tests: duplicate of a draft and of a published report both yield a draft; structure+bindings identical to source; no shared mutable reference between source and copy (deep copy); new id distinct

## Dev Notes

- Authority: FR10, architecture (services own Drizzle). Simplest correct: re-use createReport-style insert with the source document deep-copied. Deep copy matters - no aliasing the source document object (same lesson as 1.7 snapshot isolation).
- "Cleared share links": shares do not exist until Epic 3; the requirement is satisfied by the duplicate simply having no share rows. Document that share-clearing is inherent (a new report id has no shares) and will remain correct when Epic 3 adds the shares table (duplicate must not copy share rows).
- Small story; mostly a service method + one action + tests.

- e2e (`duplicate-report.e2e.ts`) follows the skeleton-instantiate desktop-only pattern (mobile-skipped, workspace list is desktop-only) and the same `Origin`-header CSRF concession the other workspace specs use.

### Completion Notes

- **`duplicateReport(id)`** (`src/lib/server/documents/reports.ts`): reads the source row (404 on unknown/malformed id), `structuredClone`s the source `document` into a fresh row with a new uuidv7, status forced to `draft`, `publishedDocument`/`publishedAt` null, `schemaVersion` carried from the document. Returns the full `Report`. The deep copy guarantees no shared mutable reference with the source (the 1.7 snapshot-isolation lesson). Share-clearing is inherent: a fresh report id has no shares, and the WHY comment records that this stays correct when Epic 3's shares table lands (duplicate must never copy share rows).
- **Route action** (`(workspace)/reports/+page.server.ts`): `?/duplicate` reads the posted id (400 if missing), calls the service, surfaces an `AppError` via `fail(status, message)`, redirects 303 to `/reports/[newId]/edit` on success. **List button** (`+page.svelte`): a secondary-variant "Duplicate" form on every report row, single-click POST via `use:enhance`.
- **Published -> draft path is tested**: the service test seeds a published source (with a publish snapshot) and asserts the duplicate is a draft with `publishedDocument`/`publishedAt` cleared, while the source row stays published.
