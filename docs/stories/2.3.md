# Story 2.3: Duplicate a Previous Issue

Status: Approved

## Story

As the author,
I want to duplicate an existing report to start the next issue,
So that the fastest path to this week's report is last week's.

## Acceptance Criteria

**Given** any report
**When** I duplicate it
**Then** a new draft is created with identical structure and bindings, cleared share links, and a draft status regardless of the source's status (FR10)

## Tasks / Subtasks

- [ ] `duplicateReport(id)` in the documents service: creates a new draft report (uuidv7) copying the source document (structure + bindings + content), status forced to draft regardless of source, published_document/published_at cleared, share links not carried (shares arrive Epic 3 - ensure the duplicate has none)
- [ ] Workspace: "Duplicate" action on the reports list and/or editor, redirect to the new draft's editor
- [ ] Tests: duplicate of a draft and of a published report both yield a draft; structure+bindings identical to source; no shared mutable reference between source and copy (deep copy); new id distinct

## Dev Notes

- Authority: FR10, architecture (services own Drizzle). Simplest correct: re-use createReport-style insert with the source document deep-copied. Deep copy matters - no aliasing the source document object (same lesson as 1.7 snapshot isolation).
- "Cleared share links": shares do not exist until Epic 3; the requirement is satisfied by the duplicate simply having no share rows. Document that share-clearing is inherent (a new report id has no shares) and will remain correct when Epic 3 adds the shares table (duplicate must not copy share rows).
- Small story; mostly a service method + one action + tests.
