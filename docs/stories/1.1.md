# Story 1.1: Project Scaffold & Quality Gates

Status: Review

## Story

As the author-developer,
I want a scaffolded SvelteKit project with quality gates,
So that every future story builds on verified foundations.

## Acceptance Criteria

**Given** a clean clone
**When** `pnpm install && pnpm build && pnpm check && pnpm test` runs
**Then** all commands succeed on Node 22 with strict TypeScript and exact-pinned dependencies
**And** the build (scaffold per AR1 + `@sveltejs/adapter-node`) produces a runnable Node server

**Given** a push to GitHub
**When** CI runs
**Then** lint, svelte-check, vitest and build jobs pass (AR8)

### Completion Notes

- No `svelte.config.js`: current sv scaffolds configure SvelteKit (including the adapter) through the `sveltekit()` plugin options in `vite.config.ts`. The architecture tree lists `svelte.config.js`; treat `vite.config.ts` as the config home unless a future need forces a split.
- tsconfig was already `strict: true` from the scaffold; verified, not added.
- Scaffold demo content (src/routes/demo/, src/lib/vitest-examples/) was removed. The landing route `src/routes/+page.svelte` plus co-located `src/routes/page.svelte.test.ts` (Vitest browser mode, chromium) replace it with real, non-placeholder coverage.
- Playwright decision: harness kept (`playwright.config.ts`, `testDir: 'e2e'`, `e2e/.gitkeep`); `test:e2e` runs `playwright test --pass-with-no-tests` so zero specs do not fail locally or in CI. First e2e story should drop the flag or simply add specs (flag is harmless once specs exist).
- `pnpm test` starts with `playwright install chromium` so the AC's clean-clone run works without a manual browser install (no-op when cached). CI additionally runs `playwright install --with-deps chromium` for runner system deps.
- Vitest is split in two projects (scaffold default): `client` (browser mode, `*.svelte.test.ts`, excludes `src/lib/server/**`) and `server` (node env, other `*.test.ts`). Story 1.2+ unit tests for server code need no browser.
- Prettier owns app code only: `.prettierignore` excludes docs/, .claude/, _bmad*, README.md, LICENSE and .github templates so `pnpm lint` does not reformat pre-existing repo prose.
- `.npmrc` is the scaffold-generated one; the local secrets-fence hook blocks reading it by name, so it was committed as generated, unmodified and uninspected.
- CI (`.github/workflows/ci.yml`): four jobs (lint, check, test, build) on push to main + PRs, Node from `.nvmrc`, pnpm version from the `packageManager` field via pnpm/action-setup@v4. Not verifiable locally; first push will prove it.
