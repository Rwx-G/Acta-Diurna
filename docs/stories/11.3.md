# Story 11.3: Reader Render and Navigation to and from a Detail Page

Status: Done

## Story

As a reader,
I want clicking an internal link to take me to its detail page and a clear way back to where I was,
So that I can drill into a finding's depth and return to the main narrative without losing my place.

## Acceptance Criteria

**Given** a rendered report with detail sections
**When** the reader loads it (with and without JS)
**Then** every detail section SSR-renders (the report is complete without JS), the main slide/scroll sequence, the progress rail, the TOC, and keyboard paging count and traverse ONLY main-flow sections, and no detail page appears "between" the cover and the close

**Given** an internal link (from a table row/cell, a matrix finding, or an inline run)
**When** the reader activates it by keyboard, touch, or pointer
**Then** the matching detail section is revealed/navigated to (reusing the fragment-deep-link machinery), focus moves into the detail page for screen-reader and keyboard users (NFR15), and any added client JS stays small and within the reader budget (NFR3) - the no-JS fallback still reaches the detail content by anchor

**Given** the reader is on a detail page reached from an origin
**When** they use the "back" affordance
**Then** they return to the origin section (the row/finding/run they came from), so drill-down is a there-and-back motion, not a one-way trip

**Given** a detail-section fragment in the URL (`#<section-id>`)
**When** the report loads
**Then** the detail page opens directly (deep-linkable like a flow section), reusing `indexForFragment` / the on-mount fragment resolution

## Tasks / Subtasks

- [x] Add a `detailIdForFragment(fragment, detailSectionIds)` helper to `navigation.svelte.ts`: returns the detail-section id named by a fragment, or null when the fragment is empty or names a main-flow section. Distinguishes a detail deep link (revealed in place) from a flow deep link (paged by `indexForFragment`).
- [x] Reveal a detail page via pure CSS `:target` (zero JS for the reveal): `.detail-host` is `display: none` until its inner `<section id>` is `:target`, then shown full-view as a fixed overlay; the main flow is hidden while a detail is open. The `:target` selectors use `:global()` because the targeted `<section>` is rendered by the child `SectionSlide` component (Svelte scopes selectors per component).
- [x] Add the click-time internal-link activation in `Report.svelte`: a `[data-internal-link]` anchor whose target is a detail page records the ORIGIN section (the nearest `[data-section-id]`), promotes the audience level if the target is hidden (reusing the flow rule), and moves focus INTO the detail page. A link to a main-flow section is left to native nav.
- [x] Add the load-time detail deep link in `onMount`: a `#<detail-id>` fragment reveals (CSS) + promotes the level + focuses the detail page, reusing the same `promoteLevelFor` / focus path the click takes; a flow fragment stays on the existing `indexForFragment` paging.
- [x] Add the "back to where you were" affordance per detail page: a plain anchor whose `href` is the recorded origin (falling back to the first flow section), so it works with no JS; with JS it also clears the recorded origin and restores focus to the origin section.
- [x] Move focus into the detail page on reveal (NFR15): the `.detail-host` is a labelled (`aria-labelledby` the section heading), `tabindex="-1"` region; `focusDetail` focuses it a frame after the `:target` reveal applies.
- [x] Tag the flow section hosts with `data-section-id` so the activation can resolve the origin.
- [x] Tests: unit (`detailIdForFragment` - detail fragment, missing hash, flow fragment returns null, empty fragment); e2e (`reader-detail-navigation.e2e.ts`, desktop + mobile) - detail SSR-complete and out of flow/TOC; table-row link reveals + focuses; matrix-finding link reveals; back returns to origin; deep link opens on load; axe-core passes with an open detail page; SSR floor (both detail sections in the served HTML).
- [x] New e2e fixture (`e2e/fixtures/detail.ts`, id `0197b300-...-000000000007`) seeded by the single-mode `global-setup.ts`: a two-detail report reached by a table `rowLinks`, a matrix finding `linkTo`, and an inline-run `linkTo`. New fixture id, so existing fixtures' snapshots stay intact; the multi-mode seed is separate and untouched.

## Dev Notes

- Authority: `docs/prd/epic-11.md` Epic 11 "Foundational design" (anchor-and-CSS first, near-zero added JS; reuse the fragment-deep-link machinery that promotes the level and scrolls to a target; the "back to where you were" affordance; deep-linkable like the existing section fragment) + Story 11.3 AC verbatim above. Builds on 11.1 (the `kind: 'detail'` section, the `view.sections` / `view.detailSections` partition, the navigation counting flow only) and 11.2 (the escaped `data-internal-link` anchors on the three carriers). Renderer-pure: `src/lib/render` imports only a validated `ReportView` + tokens, no `$lib/server`, no `{@html}`, escaped output, internal anchors only. Scopes touched: `render` (the reveal/back/focus navigation), `qa` (the fixture + e2e), `docs` (this story + CHANGELOG).
- PRESENTATION / REVEAL APPROACH (decision): CSS `:target`-driven reveal, JS only for focus + origin tracking. The detail page is a DEDICATED full-view the reader navigates TO and returns FROM (the product owner's "page dédiée"). `.detail-host` is `display: none` until its inner `<section id>` is `:target` (the native fragment match), then shown as a fixed full-screen overlay with the main flow hidden underneath. This needs ZERO JS for the reveal (the browser's `#id` jump sets `:target`), so the no-JS reader reaches and reads the detail content by anchor; the only added reader JS is focus management + origin bookkeeping. Chosen over a `data-detail-active` JS toggle precisely because `:target` keeps the reveal in CSS and off the budget. EXACT JS cost: reader budget 74.3 KB / 200 KB, +0.3 KB over 11.2's 74.0 KB - the only new reader JS in Epic 11, deliberately minimal.
- SVELTE SCOPING GOTCHA (load-bearing): the `:target` element is the `<section id>` rendered by the CHILD `SectionSlide` component, not by `Report.svelte`. Svelte scopes a component's CSS selectors to that component's own elements, so a bare `.detail-host:has(:target)` did NOT match (the e2e caught this: the detail stayed hidden). Wrapping the `:target` part in `:global()` (`.detail-host:has(:global(:target))`) lets it match the child component's targeted section. Same fix on the "hide the flow while a detail is open" selector.
- REUSE OF THE FRAGMENT-DEEP-LINK MACHINERY: the audience-level promotion that 6.1/the deep-link code already did inline in `onMount` is extracted into `promoteLevelFor(audiences)` and shared by BOTH the load-time detail deep link AND the click-time activation, so flow and detail navigation use one rule (a hidden target gets a layout box before we navigate to it). The on-mount fragment resolution now branches: `detailIdForFragment` first (reveal in place via CSS + promote + focus), else `indexForFragment` as before (page the sequence). One mechanism, two fragment kinds.
- BACK AFFORDANCE + FOCUS + A11Y: the back link is a plain `<a href="#origin">` so it works with no JS (the native hash navigation removes `:target` from the detail and restores the flow). The origin is recorded at activation (the nearest `[data-section-id]` of the clicked anchor) into a `detailOrigin` rune; the back `href` is `#${detailOrigin ?? firstFlowSection}`, so a fresh deep link or the no-JS path still has a way back to the report. With JS, `handleBack` additionally clears the origin and restores focus to the origin section (focusable in slide mode). The detail page is a labelled `role="region"` with `aria-labelledby` its heading and `tabindex="-1"`, and focus moves into it on reveal (click and deep link), so a screen-reader / keyboard user is announced onto the detail content (NFR15). axe-core passes on the rendered report with an open detail page (desktop + mobile).
- NO-JS FALLBACK (verified by the e2e SSR-floor test): both detail sections ship in the served HTML; the CSS `:target` reveal is script-free; the back link is a plain anchor. So with JS disabled, an internal link still jumps to and reveals the detail page by anchor, and the back link still returns to the report - only the focus-move and origin-restore (pure enhancements) are absent.
- DEFERRED TO 11.4 (flagged, not in 11.3 scope): the audience-level + deep-link HARDENING on detail pages. 11.3 wires the level promotion on both load-time and click-time detail navigation (reusing the flow rule) and does NOT block it; 11.4 hardens the edges (detail-only tags surfacing the switcher, the promote-on-activation guarantee for a hidden target, the level-switch show/hide on a detail page). The 11.3 fixture's detail sections are deliberately untagged, so audience promotion is exercised by the flow-side tests, not asserted on detail here.

## Dev Agent Record

### Debug Log

- First e2e run: the 5 reveal tests failed (the detail stayed hidden on `:target`). Root cause: Svelte component-scoping prevented `.detail-host:has(:target)` from matching the child `SectionSlide`'s `<section>`. Fix: `:has(:global(:target))`. Re-run green (13/13 on both projects).
- Prettier reformatted the `navigation.svelte.test.ts` import on first write; ran `prettier --write`, lint then clean.
- ESLint flagged an unused `svelte-ignore a11y_no_noninteractive_tabindex` on the detail-host (the `role="region"` makes the tabindex valid without the ignore); removed it, lint clean.

### Completion Notes

- **Reveal:** pure CSS `:target` (zero JS). `.detail-host` hidden until targeted, then a fixed full-view overlay (z-index 40, covering the chrome and rail) with the flow hosts hidden. `:global(:target)` is required for the child-component-rendered `<section>` to match.
- **Activation:** `handleInternalLink` (on the reading-surface click handler) intercepts a `[data-internal-link]` anchor to a detail page, records the origin, promotes the level, and focuses the detail page; returns a boolean so an internal-link click does not also edge-tap page. A link to a flow section falls through to native nav.
- **Deep link:** `detailIdForFragment` distinguishes a detail fragment (revealed + focused on load) from a flow fragment (`indexForFragment` paging), sharing `promoteLevelFor` + `focusDetail` with the click path.
- **Back:** a per-detail plain anchor to `#${detailOrigin ?? firstFlow}`; `handleBack` clears the origin and restores focus to the origin section. No-JS reaches back by the anchor.
- **A11y:** the detail page is a labelled `role="region"`, `tabindex="-1"`; focus moves into it on reveal (NFR15); axe-core clean with a detail page open.
- **Gates (all verified, run):** `pnpm test` 1737 passing (+4 `detailIdForFragment` unit tests); `pnpm check` 0 errors / 0 warnings; `pnpm lint` clean; `pnpm build` + `pnpm reader:budget` 74.3 KB / 200 KB (+0.3 KB over 74.0); `pnpm build && pnpm test:e2e` (single, both projects) 89 passed / 0 failed / 20 skipped (the new 13 detail-navigation tests green on desktop + mobile, incl. axe); `pnpm test:e2e:multi` 11 passed / 0 failed (the shared seed change is single-mode only; the multi seed is separate and untouched).
