# Story 6.4: Data Freshness Timestamps

**Epic:** 6 - Multi-Audience Reading & Governance (Phase 2)
**Status:** Done

As a reader,
I want data-bound blocks to show when their data dates from,
So that stale numbers are never mistaken for fresh ones.

## Acceptance Criteria

**AC1 - Unobtrusive data-as-of caption (FR16)**
Given a data-bound block
When rendered
Then the data-as-of timestamp (the explicit data-as-of field when provided, otherwise the injection timestamp from data_sets) is displayed unobtrusively.

**AC2 - Omit when no usable timestamp**
Given a data set with no usable timestamp
When rendered
Then the indicator is omitted rather than showing a misleading date.

## Dev Notes

**Where the data-as-of is sourced, and how it reaches the pure render.** The timestamp lives only in the `data_sets` row (`data_as_of` nullable, `injected_at` NOT NULL). The renderer is pure (no `$lib/server`, no DB; `toReportView` only has the document), so the timestamp must be baked into the document server-side. It is resolved and stamped at bind time, not at view-build time:

- `resolveDataAsOf(dataSet)` (ingestion) is the single precedence rule: explicit `data_as_of` else `injected_at`, returned as an ISO-8601 string. Both source columns are always populated in practice (`injected_at` is NOT NULL), so a bound data set always yields a usable instant. The "no usable timestamp" case is therefore a binding with NO data set at all (a placeholder binding authored before an upload), which never reaches this function and simply carries no `dataAsOf`.
- `applyBinding` stamps that string onto `binding.dataAsOf` whenever a block is bound, rebound (FR14 auto-rebind), or remapped (FR15) - the three write paths that already hold the `DataSet`. So the instant persists in the document exactly like `dataSetId` and the field slots, and rides into the published snapshot at publish time (a republish keeps the as-of of the data that was bound).
- `toReportView` stays untouched and pure: the bound block already carries `binding.dataAsOf`, and the render component reads it straight off `view.block`. No DB access, no async view-builder, no `$lib/server` import in the render path. This is the "already carried on the bound block" path, cleaner than making the view-builder query `data_sets`.

**Why a binding field, not a `BlockView` field.** The data-as-of is a property of the bound document (it is what was bound), so it belongs on the persisted binding next to `dataSetId`. That keeps `toReportView` and `toPreviewView` byte-identical to before (they map the block through unchanged), and the workspace preview shows the same caption from the same source with zero extra wiring.

**Additive schema, no version bump.** `dataAsOf` is `z.iso.datetime({ offset: true })`, optional. A binding without it (legacy bound block, placeholder binding, static-only block) validates and renders exactly as before - the JSON Schema artifact gains one optional property per binding node, nothing else.

**Caption design (unobtrusive, AAA, zero hydration).** `DataAsOf.svelte` renders a single small `<p class="data-as-of">Data as of <date></p>` below the block content, in `--text-sm` muted (`--report-text-muted`) - the same caption treatment the chart legend and KPI labels already use, so it sits quietly under the data and never dominates. One shared component feeds table/chart/kpi so the three cannot drift. It is static SSR markup (no `$props` interactivity, no client JS), so the reader budget is unaffected.

**Deterministic formatting (no hydration mismatch, no locale leak).** The date is formatted with a module-level `Intl.DateTimeFormat('en-GB', { day:'numeric', month:'short', year:'numeric', timeZone:'UTC' })` -> e.g. `8 Jun 2026`. Fixed locale + UTC makes the string byte-identical on the server and any client, so SSR never mismatches hydration and the caption never depends on the reader's locale or timezone. `formatDataAsOf` returns `null` for `undefined` or an unparseable instant, and the `{#if}` omits the caption entirely in that case - never a placeholder or a misleading "unknown" date (AC2).

**Escaping.** The instant is interpolated as text (`{formatted}`), escaped by Svelte like every other binding. A malformed/script-like value formats to `null` and renders nothing, so it can never reach the DOM as markup.
