# Story 1.2: Document Schema v1 - the Published Contract

Status: Done

## Story

As an author (human or agent),
I want a versioned document schema with actionable validation,
So that any producer can create a valid report and know precisely why an invalid one fails.

## Acceptance Criteria

**Given** the `src/lib/schema/` package (Zod 4, AR2)
**When** a document with section + text/table/chart/kpi/image blocks is validated
**Then** it parses with full TypeScript types, and audience-tag fields are accepted (rendering deferred to P2)

**Given** an invalid document (missing field, wrong type, unknown block)
**When** validated
**Then** the error names the block path and field with a hint, in problem-details shape (FR2)

**Given** the schema
**When** the `z.toJSONSchema()` export runs
**Then** a valid JSON Schema (draft 2020-12) is produced with version identifier `1`
**And** example documents (minimal + full-featured) live beside the schema and validate in tests

## Tasks / Subtasks

- [x] Define `src/lib/schema/` package: document root (version field = 1, title, theme ref, sections), section (id, title, audience tags optional, annex flag, blocks), and the five block types (text, table, chart, kpi, image) with data-binding declarations (expected fields) where applicable
- [x] Audience tags: optional `audiences` array on sections and blocks (values: summary/full/technical) - accepted and typed, not yet rendered
- [x] Actionable error layer (`errors.ts`): Zod error map producing `{path, message, hint}` entries; problem-details shaping helper

- [x] Example documents: `examples/minimal.json` and `examples/full.json` beside the schema; co-located Vitest tests validating both plus a corpus of invalid documents asserting exact error paths/hints
- [x] Version dispatch skeleton (`versions/`): registry mapping version -> schema, unsupported-version error with supported range (groundwork for FR7)

### Completion Notes

- **zod 4.4.3**, exact-pinned. JSON Schema export uses native `z.toJSONSchema()` with `io: 'input'` so defaulted fields (e.g. `table.options.stickyHeader`, default `true`) stay optional in the published artifact - it describes what producers write, while `validateDocument` returns the output side with defaults applied (`DocumentV1` vs `DocumentV1Input` types).
- **Validation contract** (`errors.ts`): `validateDocument(unknown)` returns `{ok: true, document} | {ok: false, errors: [{path, message, hint?}]}`. Paths are human-readable (`sections[0].blocks[0].alt`); root-level issues use path `document`. `toProblemDetails(errors)` shapes RFC 9457 (status 422, type `/problems/document-validation`) for the API layer (D9). Stories 1.5/1.6 and the API should consume `validateDocument` + `toProblemDetails`, never raw ZodError.
- **Hint engine**: custom-issue `params.hint` first, then field-specific hints (`alt`, `assetId`), then code-based fallbacks (union options list, allowed values, array minimums, expected type, format guidance). Schema-level messages cover version literal, slugs, alt, assetId, link protocol.
- **XSS-safety is structural**: text blocks are paragraphs of inline runs `{text, bold?, italic?, link?}` - no HTML-bearing field exists; link hrefs are restricted to http(s) (rejects `javascript:`); images reference uploaded assets by UUID only (no remote URLs).
- **Data-bound blocks** (table/chart/kpi): static data, `binding`, or both; "neither" fails with an actionable custom issue on the static-data field. `binding.dataSetId` optional until Epic 2 ingestion; `binding.fields` declares expected names + types (`string|number|date|boolean`).
- **Ids are slugs** (`^[a-z0-9]+(?:-[a-z0-9]+)*$`); lowercase UUIDs match the same pattern, so generated and hand-written ids share one rule. `theme` is an optional slug reference (theme registry arrives with the renderer story).
- **Version registry** (`versions/index.ts`): `schemaRegistry`, `getSchema(version)` throwing `UnsupportedVersionError` (carries `requestedVersion` + `supportedVersions`), `SUPPORTED_VERSIONS` derived from the registry. v2 later means: add `versions/v2.ts`, register it, write the N-1 migration (FR7).
- **`pnpm schema:export`** runs `node scripts/export-schema.ts` using Node's native type stripping (requires Node >= 22.18; CI's `.nvmrc` resolves to latest 22.x). This works because schema-internal imports use explicit `.ts` extensions (allowed by `rewriteRelativeImportExtensions` already present in tsconfig) - keep that convention inside `src/lib/schema/` and `scripts/`. `static/schema/v1.json` is committed; a test fails if it drifts from `toJsonSchema()` (regenerate via `pnpm schema:export` after any schema change). `/static/` is prettier-ignored, so the artifact's formatting is owned by the export script.
- **Published JSON Schema nuance**: with `io: 'input'`, object schemas emit no `additionalProperties: false`, and zod's parser strips unknown keys instead of rejecting them. Unknown keys are therefore tolerated-and-dropped, not errors - consistent between artifact and runtime.
- Example documents: typed constants (`examples/minimal.ts`, `examples/full.ts`) plus serialized copies (`minimal.json`, `full.json`) kept in sync by equality tests; the full example exercises all five blocks, audiences, annex, bindings with and without `dataSetId`, and a block carrying both static data and a binding.

**QA iteration 1 (2026-06-12):**

- **Version dispatch**: `validateDocument` now peeks `version` leniently and routes through `getSchema(version)` (registry, FR7). Missing or unsupported version returns a single `{path: 'version'}` error with the supported range as hint - never the misleading `invalid_value` from the v1 literal. Non-object input still parses against v1 for the standard root-level `document` error.
- **DoS bounds**: every array and string in the schema is capped with a clear message: sections 100, blocks/section 200, paragraphs 500, runs/paragraph 200, run text 5000, titles/labels/names/units/axis labels/ids 300, alt/caption 500, link href 2000, table columns 100, rows 10000 (cells 5000, row keys 300), chart series 50, points/series 10000, kpi items 50, binding fields 100, audience tags 3. Representative over-limit tests for sections, runs and rows assert exact paths. Artifact regenerated.
- **Hint precedence** restructured in `hintForIssue`: custom `params.hint` > issue-code hint > field hint; generic expected-type guidance ranks last. `assetId` format errors now get the UUID-format hint (code-specific), missing `alt`/`assetId` keep their field hints. Dead `version` special case inside `invalid_value` removed (unreachable after dispatch).
- **Export hygiene**: `documentSchemaV1` has a single export site (`versions/index.ts`); `index.ts` re-exports from there and the unused `documentSchema` alias is removed.
- **JSON Schema**: `toJsonSchema()` post-processes the link `href` node with `"pattern": "^https?://"` (zod keeps the protocol restriction internal; the artifact now advertises it).
- Mediums: four hint assertions tightened from `toContain` to `toBe`; `requireStaticDataOrBinding` keyed on `'rows' | 'series' | 'items'` (Record cast removed); `SUPPORTED_VERSIONS` typed `readonly SupportedVersion[]` via `as const satisfies`; engines floor raised to `node >= 22.18` (type-stripping floor); text `paragraphs` now `.min(1)`.
- Gates re-run: `pnpm lint`, `pnpm check` (0/0), `pnpm test` (39 unit tests: 38 server + 1 browser), `pnpm build`, `pnpm schema:export` idempotent.
