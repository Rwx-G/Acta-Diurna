# Story 7.7: Callout / Admonition Block

**Epic:** 7 - Rich Block Catalogue (Phase B)
**Status:** Done

## Story

As an author or agent,
I want a tonal callout box with an optional icon, kicker, and rich body,
So that I can elevate a verdict, a summary, a warning, or a resource list above the body flow.

## Acceptance Criteria

**Given** a `callout` block with a `tone` (e.g. `info` | `success` | `warning` | `danger` | `neutral`), an optional `icon` (7.6) and `kicker` label, and a rich-text body
**When** rendered
**Then** it renders as a tinted, left-accent-bordered box whose colour derives from the tone (via the theme/scale, not raw hex), with the optional icon + uppercase kicker header and the escaped rich-text body

**Given** the tone
**When** rendered
**Then** tone is conveyed by more than colour (the kicker label and/or icon), so the callout meaning survives without colour (NFR14), holding AAA report content on the default theme

**Given** an invalid tone or an unknown icon key
**When** validated
**Then** an actionable problem-details error names the offending field (FR2 parity)

**Given** the block
**When** audited
**Then** it is SSR, Zod-validated, renderer-pure (escaped body, no raw HTML), within the reader budget

## Dev Notes

### Tone colour comes from the token system, not a scale

The 7.7 tone is a CLOSED enum, deliberately NOT a document `scale` reference. A callout's
colour language is a fixed, theme-owned semantic set, so a callout renders with no `scales`
declaration and an existing document gains the block with zero authoring overhead. This is the
same stance the comparison-matrix `treatment` status tint takes (a fixed two-state semantic tint
from theme tokens, never a scale, because status is a closed enum).

The five tones map to five new semantic tokens on the theme surface,
`--report-tone-{info,success,warning,danger,neutral}` in `src/app.css`, defined for both the
default and midnight themes. The renderer reads ONLY these tokens (via a `tone-<tone>` class that
sets a `--tone-color` custom property); no raw hex lives in the component, so a new theme re-skins
every callout with no component change (the FR39 token stance, consistent with the trend colours
and the categorical palette).

### Tone-colour / token decisions

| Tone | Default (on stone `#f5f1e8`) | Midnight (on `#14131f`) | Reused hue |
| --- | --- | --- | --- |
| info | `#1c4a7e` (8.0:1) | `#6ea8e0` (7.3:1) | chart-3 blue |
| success | `#2f6b4a` (5.6:1) | `#6fbf95` (8.4:1) | trend-up green |
| warning | `#8a5a13` (5.2:1) | `#d6a85a` (8.4:1) | amber / chart-4 |
| danger | `#a23b3b` (5.8:1) | `#f08a8a` (7.6:1) | trend-down red |
| neutral | `#4a4960` (7.7:1) | `#b9b4c4` (9.1:1) | text-muted |

Ratios are the tone accent against the report background. The tone colours reuse the existing
report-content hues (the chart palette, the trend pair, muted text) so a callout reads in the same
colour language as the rest of the report.

### Accessibility (NFR14) and the AA decorative floor

Tone is conveyed by MORE than colour: the renderer pairs the tint with the uppercase kicker label
and/or the icon, so the callout's meaning survives without colour. The body text stays
`--report-text`, which holds AAA on the default theme (the contrast regression test asserts it).

The tone accent itself (the left border and the icon + kicker label) is a DECORATIVE accent, not
prose, so its contract is the AA floor on the report background, the same documented stance the
categorical swatches and the KPI trend colours take. All ten tone/theme pairs clear AA (most clear
AAA); `contrast.test.ts` asserts the floor so a future token edit cannot regress it silently. The
tinted box background is a low (8%) wash of the tone over the surface and is not contrast-gated
against the body text.

### Rich-text body reuse

The body reuses the text block's `paragraphSchema` / `inlineRunSchema` verbatim, and the renderer
renders it the way `TextBlock.svelte` does: Svelte text interpolation (escaping), only the
bold/italic/link marks the schema permits, link hrefs http(s)-restricted by the schema with
`rel="external noopener noreferrer"`. No `{@html}`, no raw HTML. The editor edits the body as
plain-text paragraphs with the same flatten-on-edit MVP behaviour the text-block editor uses.

### Block-type count fan-out

Adding the eleventh block type required two existing tests to roll forward (legitimate, not a
contract change): `errors.test.ts` (the unknown-block-type hint now lists `callout`) and
`json-schema.test.ts` (the block union is now eleven members). The `StructureTree.svelte`
exhaustive `never` switch required a `callout` case (svelte-check gate). The document-level
cross-reference pass (`scales.ts`) needed no change: it is an `if/else if` chain with no `else`,
and a callout carries no scale reference.
