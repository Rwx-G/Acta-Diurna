# Story 8.1: Operating-Mode Foundation and SMTP Transport

**Epic:** 8 (Identity & Multi-Author, SMTP-gated)
**Status:** Review

## Story

As an operator,
I want the instance to choose single- vs multi-author mode from the SMTP environment, validated fail-fast at boot,
So that turning multi-author on or off is a deliberate ops action with no silent lockout.

## Acceptance Criteria

**Given** SMTP is NOT configured in the environment
**When** the app boots
**Then** it resolves to SINGLE mode (password author, consultation-token shares), exactly as today, and `AUTHOR_EMAIL_DOMAIN` / `INITIAL_OWNER_EMAIL` are not required

**Given** SMTP IS configured (the all-or-nothing SMTP block is present and shape-valid)
**When** the app boots
**Then** it resolves to MULTI mode AND the env validation requires `AUTHOR_EMAIL_DOMAIN` and `INITIAL_OWNER_EMAIL` (with `INITIAL_OWNER_EMAIL` inside `AUTHOR_EMAIL_DOMAIN`); a missing or out-of-domain value FAILS the boot with an actionable message (never a silent lockout)

**Given** a bare internal relay (`SMTP_TLS_MODE=none`, no `SMTP_USER` / `SMTP_PASSWORD`, port 25)
**When** the mailer transport is built and `transporter.verify()` runs
**Then** it connects with `secure:false`, no `requireTLS`, and no `auth` object, and verify succeeds (the anonymous-smarthost profile works); STARTTLS/TLS + authenticated profiles still work unchanged

**Given** an operator wants to validate SMTP before relying on it
**When** they run the provided CLI connection test (`pnpm smtp:test` or the docker-exec equivalent)
**Then** it runs `transporter.verify()` against the configured env and reports success or the exact, credential-redacted failure - and this command NEVER changes the operating mode (the mode is env-only)

**Given** the resolved mode
**When** any downstream code needs it
**Then** a single mode resolver exposes it (`single` | `multi`) so auth, sharing, and the UI branch on one source of truth

## Dev Notes

- This is the Epic 8 FOUNDATION. It adds ONLY the env seam, the mode resolver, the transport hardening, and the CLI. It does NOT touch authentication, ownership, or sharing (stories 8.2-8.4). An SMTP-absent (single-mode) instance is byte-identical to before: the new env vars stay optional, the mode resolver returns `single`, and the mailer's starttls/tls profiles are unchanged.
- The mode is a pure function of the SMTP env, reusing the SAME `anySmtp`/`SMTP_HOST` signal the env refine and `mailerConfig()` already key on - so no separate "mode" variable can drift from the SMTP configuration. The all-or-nothing SMTP refine guarantees a present `SMTP_HOST` implies a complete, multi-mode-valid block.
- Fail-fast anti-lockout: multi mode has no password fallback and no break-glass, so configuring SMTP without a valid in-domain `INITIAL_OWNER_EMAIL` would lock everyone out. The refine therefore makes both identity vars required AND domain-matched in multi mode; the container refuses to boot with an actionable message rather than starting an unauthenticatable instance. The domain compare is case-insensitive (`emailDomain()` lowercases the email's domain part; `AUTHOR_EMAIL_DOMAIN` is lowercased for the compare only, the stored value is preserved).
- SMTP transport hardening for the bare port-25 smarthost: the `none` mode now emits NO `requireTLS` key at all (a `requireTLS:false` was harmless but a `requireTLS` of any value risks a STARTTLS probe on a relay that does not advertise it), and the `auth` object is only attached when a user is configured - passing `auth: { user: undefined }` can coerce an unwanted AUTH on a relay that accepts anonymous submission. `transporter.verify()` then attempts no authentication and no STARTTLS on the anonymous profile.
- The CLI (`scripts/smtp-test.ts`) builds the transport with `createTransport` DIRECTLY (mirroring the mailer's tiny mapping) rather than importing `mailer.ts`, because the mailer uses the `$lib` alias that only Vite/SvelteKit resolves - a plain `node scripts/*.ts` cannot. It parses the env through the same `parseEnv` the app boots with, so a malformed SMTP block fails here with the identical message. It is a pure ops debug helper: it never reads or writes any "mode" state.
- `READER_EMAIL_DOMAINS` is parsed now (story 8.1 owns the env surface) but consumed later (story 8.5). It transforms to a trimmed, lowercased, non-empty list so 8.5 matches against a clean array.
