# Story 7.10: Structured List and Steps Block

**Epic:** 7 (Report Brick Library, Phase B)
**Status:** Review

## Story

As an author or agent,
I want an ordered or unordered structured list, including a numbered-steps / procedure variant,
So that remediation procedures and checklists render as first-class blocks, not ad-hoc prose.

## Acceptance Criteria

**Given** a `list` block with an `ordered` flag and `items` (each: a lead `term`/`title` and an optional rich-text `description`)
**When** rendered
**Then** it renders as an `<ol>` (numbered, for procedures/steps) or `<ul>` (unordered) with the bold lead per item and the escaped description, semantically correct for screen readers

**Given** an ordered steps list
**When** rendered
**Then** the step numbering is the native list ordinal (no hand-authored numbers), so reordering items renumbers automatically

**Given** the block
**When** audited
**Then** it is SSR, Zod-validated, renderer-pure, passes axe-core, within the reader budget

## Dev Notes

- The `ordered` flag is the only state that distinguishes a numbered procedure from an unordered checklist: the renderer maps it to a real `<ol>` or `<ul>`, so the step numbering is the native list ordinal. The schema deliberately carries NO per-item number, so reordering items renumbers automatically and a hand-authored number can never drift from its position (AC2).
- Each item carries an optional bold lead `term` and an optional rich-text `description`; at least one must be present (a `.refine` on `listItemSchema`). An empty item is a validation error.
- The `description` reuses the text block's `paragraphSchema` (paragraphs of inline runs) verbatim, so it renders escaped through the SAME marked-run snippet the callout (7.7) and code (7.8) blocks use - bold/italic, the inline-code chip, and http(s) links all work. No new inline vocabulary.
- `items` capped at `MAX_LIST_ITEMS = 100` (a procedure past 100 steps is a structural smell - split it), `description` capped at `MAX_LIST_ITEM_PARAGRAPHS = 50` (the callout body ceiling). `term` bounded at 200 characters.
- List text uses `--report-text` / theme tokens (AAA report content on the default theme); no raw hex in the component. Zero hydration: the list ships no client JS.
- The editor edits the description as plain-text paragraphs (the callout flatten-on-edit pattern); removing the last description paragraph drops the whole description, so a term-only item stays schema-valid.
