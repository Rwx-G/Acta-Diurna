# Story 6.1: Audience Levels

**Epic:** 6 - Multi-Audience Reading & Governance (Phase 2)
**Status:** Review

As a reader,
I want to switch the report between summary, full, and technical levels,
So that one report serves my role.

## Acceptance Criteria

**AC1 - Reader level switch (FR28)**
Given a document with audience-tagged blocks (tags exist since schema v1)
When I switch level in the reader
Then visible blocks re-render instantly to the selected level; untagged blocks appear at every level; default is "full".

**AC2 - No tags, no switcher**
Given a report with no tags at all
When rendered
Then it renders identically for everyone and the level switcher is hidden.

**AC3 - Author per-level preview**
Given the workspace editor
When the author tags blocks
Then per-level preview shows exactly what each audience sees.

## Dev Notes

**Switcher design.** The block content is rendered SSR at every level, exactly as before. The only added client behaviour is a small radio group (`LevelSwitcher.svelte`) whose selection sets `data-level` on the report root. Visibility is pure CSS: `.report[data-level='X'] :global([data-audiences]:not([data-audiences~='X'])) { display: none }`. Each block wrapper carries `data-audiences` (space-separated, canonical order) and each section host the same; untagged elements carry no attribute, so no rule matches them and they stay visible at every level. Switching is an instant attribute swap, no re-render and no round-trip. The `:global()` is required because the hidden elements live in child components (BlockRenderer's `.block`), which Svelte scoped CSS would not reach; the selector stays anchored under the scoped `.report[data-level]` so it cannot leak.

**Why `display: none`.** It removes the excluded block from layout AND the accessibility tree, so a screen reader at "summary" never reaches "technical" content (AC requirement). `visibility: hidden` or `hidden`-attribute toggling were rejected: the former still reserves space, and although `[hidden]` also removes from the a11y tree, the CSS-data approach needs zero per-block JS (the data attribute is already SSR-emitted), keeping the reader JS budget flat.

**No-JS fallback.** With JS disabled the root carries no `data-level` (it is set only when `hasAudiences` and only drives the CSS once present), so no hide rule matches and every block renders - the reader gets the full report, not a broken one. This is a superset of the default `full` view; an untagged document is identical either way. Choice: render all content server-side rather than pre-filtering to `full`, because the no-JS reader is better served seeing everything than silently losing technical/summary-only blocks they cannot switch to.

**Shared predicate.** `isVisibleAtLevel` and `audiencesAttr` (schema `audience.ts`) are the single source of truth. `audiencesAttr` feeds the reader/preview CSS-data; `isVisibleAtLevel` is the programmatic equivalent for any future SSR pre-filter or test. The reader switcher, the author preview and the no-JS fallback all derive from the same `data-audiences` serialization, so they cannot diverge.

**Author preview parity.** The workspace LivePreview embeds the same `Report` component with `embedded`; the switcher and the `data-level` CSS are identical, so the per-level preview shows exactly what the reader sees (AC3). The author still edits every block; only the preview's visibility simulates a level.

**Reader JS budget (NFR3).** 72.4 KB gzipped after this story, within the 200 KB budget. The switcher adds a tiny component reusing native radio handling; no measurable budget change.

**Unverified.** The Playwright e2e (`reader-accessibility.e2e.ts`) needs a running app and a Postgres-backed fixture; not runnable in this environment. The a11y guarantee (hidden blocks removed from the tree via `display: none`) is covered by the `Report.svelte` browser component test asserting `getComputedStyle(...).display === 'none'` for a level-excluded block. The switcher is a standard labelled radio group, which the existing axe gate accepts.
