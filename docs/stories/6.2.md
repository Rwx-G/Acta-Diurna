## Dev Notes

**Notes-privacy approach (the load-bearing requirement).** Speaker notes are author-only and must never reach a reader. Two independent guarantees enforce this:

1. The reader view-model omits notes. `toReportView` maps a `Section` to a `SectionView` that has no `notes` field, so the rendered SSR HTML and the `view` prop a reader route serializes carry none. This was already true; a regression test now pins it.
2. The reader-served document is stripped. The public reader route `/r/[token]` returns the raw `DocumentV1` in its load payload (serialized to the client for hydration). If notes lived on those sections, they would ship in the hydration data even though the rendered HTML hid them. So `getPublishedDocument` - the single chokepoint every reader path funnels through - strips `notes` from every section before the document leaves the server (`stripSpeakerNotes`). The draft and the stored snapshot keep their notes untouched; only the served copy is stripped.

The presenter view, by contrast, is an owner-scoped WORKSPACE route, so it is allowed to read notes. It deliberately does NOT use `getPublishedDocument` (which strips them); it loads the report's own `publishedDocument` through the owner-scoped `getReport`, then pairs each render section with its notes via `toPresenterSections`. Notes only ever exist on the presenter section pairs, never on the reader `SectionView` shape.

**Additive schema, no version bump.** `notes` is optional with a 20000-char ceiling. A section without notes validates and renders exactly as before, so no migration and no version bump - the JSON Schema artifact gains one optional property.

**Owner-scoping and the 404 seam.** The loader resolves the author scope and calls `getReport(id, scope)`. In multi mode the owner predicate ANDs into the lookup, so a foreign id or an unknown id both raise the same not-found `AppError`, mapped to a 404 - no existence oracle (story 8.2 tenancy). In single mode the predicate is a no-op, byte-identical to the pre-tenancy query. The loader test reuses the share-page tenancy pattern.

**Meeting mode.** A client-side toggle. When on, `presentedSequence` drops every `annex` section, so prev/next, the position counter, and the next-section preview never land on one. `indexAfterMeetingToggle` keeps the presenter anchored on the same document section across the toggle, or on the nearest surviving earlier section when the section in view is itself an annex that gets hidden. The toggle is also bound to the `m` key.

**Local only (FR29, no-real-time non-goal).** All presenter state - current index, meeting mode, timer - lives in the one window. No websocket, no device sync, no real-time. The elapsed timer is wall-clock UI state (a 1 s interval) that starts on open and has a reset control. The deterministic sequencing the timer and renderer read is the pure `presenter-sequence.ts` module; the timer itself is component state.

**Render reuse.** The current section renders through the existing reader render component `SectionSlide` (scroll mode), threaded with the document `scales`, `matrixBlocks`, and resolved `theme` from the same `toReportView` output - so the presenter stage looks like what readers see. The presenter container carries `data-theme` so the `--report-*` tokens resolve exactly as on the reader.

**Reader budget unaffected.** The presenter is a hydrated workspace route, outside the `/r/[token]` reader closure the budget measures. `reader:budget` reports 72.5 KB, unchanged.
