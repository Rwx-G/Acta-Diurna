# Story 7.4: Set-Membership (UpSet) Matrix Block

Status: Done

## Story

As an author or agent,
I want an UpSet-style matrix derived from the same findings,
So that coverage by source-combination is visible at a glance, with zero extra data entry.

## Acceptance Criteria

**Given** a Set-Membership block referencing a Comparison Matrix block by id (`sourceBlockId`)
**When** rendered
**Then** it derives one row per present intersection - findings grouped by the exact set of sources where `state != none` - and renders each row as a dot pattern (one dot per source in the sources scale, filled when the source is in that set, with a line connecting the filled dots) (FR42)

**Given** an intersection row
**When** rendered
**Then** the findings in that intersection appear beside the pattern as severity-coloured pills (from the severity scale) carrying their short tag/label

**Given** the dot-and-line pattern
**When** rendered
**Then** it is SSR SVG built with d3-scale / d3-shape (zero hydration, no LayerChart), within the reader budget (NFR3), and passes axe-core (the SVG carries an accessible text alternative summarising each intersection)

**Given** a `sourceBlockId` that does not resolve to a Comparison Matrix block in the same document, or findings that are all `none`
**When** validated or rendered
**Then** validation flags the dangling reference (problem-details), and an all-`none` data set renders a neutral empty state rather than crashing

NO findings of its own - it derives everything from the referenced matrix (epic: "references that block by id; it never re-enters findings"). Optional render hints allowed (e.g. a `title`), but no data. Export from `src/lib/schema/index.ts`.

This is the second whole-document cross-reference 7.1 establishes the locus for (the first being scale refs); reuse the same path-construction helper.
- [x] Intersection-derivation algorithm as a PURE ISOMORPHIC function (`src/lib/render/blocks/upset-geometry.ts`, sibling to `chart-geometry.ts`, no DOM, no server): given the referenced matrix's findings + the sources-scale entry order, group findings by the EXACT set of sources where the source FOUND the finding (DECIDED SEMANTICS: `state === 'found'` only, the conventional coverage UpSet; see Dev Agent Record for the AC `!== none` deviation and the isolated predicate location). Produce one row per PRESENT intersection (an intersection with zero findings is omitted), each row carrying: the membership set, the findings in it (with their `severity` + `tag`/`label`), and a count. Order rows deterministically (descending finding count, then descending membership size, then canonical key). The function returns plain data (membership booleans per source, finding pill descriptors, dot/line pixel geometry via d3-scale/d3-shape) - NEVER the raw findings beyond what the SVG + pills need (NFR3).
- [x] SSR SVG render component `src/lib/render/blocks/SetMembershipBlock.svelte` (pure SSR, zero hydration, the `ChartBlock.svelte` pattern exactly): a static `<svg>` built from the geometry - one dot per sources-scale entry per intersection row (filled when in the set, hollow otherwise), a connecting line through the filled dots (d3-shape `line`), and the severity-coloured finding pills beside each row (`scaleEntryColor` from the severity scale, 7.1). Reuse the chart colour-token approach. `role="img"` + a `<title>`/`<desc>` accessible text alternative SUMMARISING each intersection (generalized, no domain vocabulary) so the pattern is not the sole signal (AAA, the AC). - [x] All-`none` / empty intersection neutral state: when every finding in the referenced matrix has an empty found-set (or the matrix has no findings), there are no present intersections - render a neutral empty state ("No source coverage to chart yet."), NEVER a crash or an empty SVG (the AC). The derivation function returns an empty rows array; the component branches to the empty state.

- Proposed `set-membership` Zod shape (the load-bearing contract; `blocks/set-membership.ts`):

```
export const setMembershipBlockSchema = z.object({
  type: z.literal('set-membership'),
  id: idSchema,
  audiences: audiencesSchema.optional(),
  sourceBlockId: idSchema,                              // id of a comparison-matrix block in the same document
  title: z.string().min(1).max(300, 'Set-membership title too long: 300 characters maximum.').optional()
});
```

- Intersection-derivation contract (the load-bearing pure function, `upset-geometry.ts`):
  - Input: the referenced matrix's `findings` + the sources-scale entry keys in scale order.
  - For each finding, its membership set = `{ sourceKey | finding.sources[sourceKey]?.state !== 'none' }` (an ABSENT source record key counts as `none` - it is not in the set; consistent with 7.2's "a missing record key renders as none"). The intersection key is the membership set's source keys sorted in sources-scale order (a stable, canonical key).
  - Group findings by that key; emit one row per NON-EMPTY group (a present intersection). A finding whose membership set is empty (all-`none`) belongs to the empty intersection, which is OMITTED from rows (it has no dots to draw) - it is NOT a crash, it is just not charted. When EVERY finding is empty-set (the all-`none` AC), rows is empty and the component shows the neutral empty state.
  - Row order: descending finding count, then descending membership size, then the canonical key (deterministic, conventional UpSet). Document the exact tiebreak.
  - Output: per row { membership: boolean[] aligned to the sources-scale order, findingPills: [{ severity, tag/label }], count, dot/line pixel geometry }. Ship ONLY this, never the raw `text`/`treatment` of the findings (NFR3 "no raw dataset beyond what the SVG needs").
- Why a pure geometry module sibling to `chart-geometry.ts`: it keeps the math isomorphic and testable without a DOM, and keeps the SVG component a thin static emitter (the 1.6 D12 SSR-only chart pattern). d3-scale (a band/point scale over the sources for dot x-positions, over the intersection rows for y) + d3-shape (`line` for the connector) - the EXACT two packages already in `chart-geometry.ts`, no new dependency (CLAUDE.md "no new dependencies"; epic "no new dependency beyond the existing d3-scale/d3-shape").
- Combinatorial bound: an UpSet over N sources has up to 2^N possible intersections, but only PRESENT ones are emitted and the row count is bounded by the finding count (`MAX_FINDINGS = 500`, 7.2) - at most one row per distinct membership set actually present, never 2^N empty rows. The sources scale is capped at 24 entries (7.1), so a row's dot count is <= 24. SSR stays within NFR1. No unbounded surface.
- Dangling-ref + cross-document scope: `sourceBlockId` must resolve WITHIN THE SAME DOCUMENT (epic: "a comparison-matrix block in the same document"). The resolution walks the document's sections for a block with that id and `type === 'comparison-matrix'`. This is a whole-document concern (the referenced block can be in any section), so it lives at the 7.1 document superRefine locus, not the block-local superRefine. A `set-membership` pointing at a `table` block id, or at a non-existent id, is the dangling-ref FR2 error.
- AMBIGUITY for the product owner (do not invent): (a) the EXACT intersection row ordering (descending count then membership size proposed - the conventional UpSet sort) vs. a fixed author-meaningful order - recommend the conventional descending-count sort (it surfaces the biggest coverage gaps first), but confirm. (b) whether a source whose state is `missing` (the source looked, did not find) counts as IN the membership set or OUT - the AC says "where `state != none`", which puts `missing` IN the set alongside `found`; CONFIRM this is intended (UpSet conventionally charts "did this source have an opinion" which `missing` arguably is, vs "did this source cover it" which is only `found`) - this is the single most load-bearing semantic of the whole block and the epic's literal wording (`state != none`) is the current contract; flag it explicitly before implementing. (c) whether multiple `set-membership` blocks may reference the same matrix - recommend yes (no reason to forbid; each derives independently), no constraint needed, but confirm.

## Dev Agent Record

### Debug Log

- **Membership semantics: found-only, NOT the AC's `!== none`.** The AC text and Dev Notes say "the exact set of sources where `state != none`" (which would put `missing` IN the set). The implementation decision (flagged ambiguity (b), resolved by the product owner before coding) is the conventional COVERAGE UpSet: a source is in the set only when it FOUND the finding (`state === 'found'`). `missing` and `none` are OUT. This is the single most load-bearing semantic; the AC wording was the open question and the decision overrides it. The predicate is isolated in ONE place - `isInMembershipSet(state)` in `src/lib/render/blocks/upset-geometry.ts` - so flipping to "found or missing" (every source that had an opinion) is a one-line change there (`state === 'found' || state === 'missing'`) with no other edit. If the AC is meant to be authoritative over the decision, raise it; the flip is trivial and isolated by design.
- **Resolving the referenced matrix needs a document-wide block lookup, not just `scales`.** A set-membership block's `sourceBlockId` can point at a comparison-matrix in ANY section, but `BlockRenderer` only received `view.block` + `scales`. Added a `matrixBlocks: Map<string, ComparisonMatrixBlock>` to `ReportView` (`document-view.ts`, both builders), populated by `collectMatrixBlocks` over the parsed sections, and threaded it `Report -> SectionSlide -> BlockRenderer -> SetMembershipBlock` exactly as `scales` is. The preview path collects matrices from the per-block-validated views, so a transiently invalid sibling never blocks the UpSet from resolving its source mid-edit.
- **Cross-ref pass extended, not duplicated.** `validateScaleReferences` (`scales.ts`) gained a `set-membership` branch: it first builds `collectMatrixBlockIds` (a set of every comparison-matrix block id in the document), then for each set-membership block resolves `sourceBlockId` against that set. A dangling id, or an id pointing at a non-matrix block (not in the set), is one `ScaleReferenceIssue` at `['sections', i, 'blocks', j, 'sourceBlockId']`, re-emitted through the existing v1 superRefine pipeline as FR2 problem-details. The function signature widened to `{ type: string; id?: unknown }` per block (it needs the id to index matrices); the seam's existing callers were unaffected (id is optional).
- **Empty-set handling: explicit "(none)" row, but only beside real coverage.** A finding no source found belongs to the empty intersection. Decision: emit it as an explicit "(none)" row (dotless, "Found by no source: ..." summary) so orphaned findings are never silently dropped - BUT only when at least one non-empty intersection also exists. When EVERY finding is empty-set (the all-`none`/`missing` AC), there is no coverage to chart: the empty group is dropped so `rows` is empty and the component shows the neutral empty state, never a single dotless row or an empty SVG. This is the one place the "(none)" row is conditionally suppressed; it lives in `computeUpSetGeometry` (the `hasPresentIntersection` guard).
- **`{' '}` in `<desc>` tripped `svelte/no-useless-mustaches`.** The per-row `<desc>` join needed a space separator; a `{' '}` mustache is flagged by the lint rule. Replaced the `{#each}` in `<desc>` with a derived `descText` string (`rows.map(r => r.summary).join(' ')`) interpolated once - cleaner and lint-clean. Each summary already ends with a period.
- **Type-name collision in `BlockRenderer`.** Importing the `ComparisonMatrixBlock` TYPE alongside the `ComparisonMatrixBlock` component (same name) is a duplicate-identifier parse error. Aliased the type import to `ComparisonMatrixBlockType`.
- **Layout fix (2026-06-12): finding pills aligned BESIDE their intersection row, not stacked below.** The original layout rendered the dot-matrix SVG, then a separate pills `<ol>` BELOW it, so the visual link "this source combination -> these findings" was broken. New layout: a CSS grid (`.upset-grid`) whose row tracks are fixed at the geometry's `rowHeight` (with the SVG's top/bottom margins as spacer tracks). The dot-matrix SVG occupies grid column 1 and spans every track (`grid-row: 1 / -1`, `height: 100%`), so - since the track total equals `viewBox.height` - it renders at 1:1 with no vertical scaling and each internal SVG row maps to exactly one track. The pills `<ol>` is `display: contents` so each `<li>` is placed directly into the parent grid at column 2, track `rowIndex + 2` (after the top-margin spacer), top-aligned beside its row's dots. The dot x-positions are unchanged, so source columns still line up vertically across rows and the source labels stay under the columns. Geometry exposed two new fields (`marginTop`, `marginBottom`) for the spacer tracks; `isInMembershipSet` and all derivation logic are untouched (layout-only). Responsive: at the 768px reader breakpoint the grid dissolves to a single column (full-width SVG on top, then the per-row pills stacked under it in row order) - the graceful narrow-screen fallback; desktop default is pills-beside-row. Preserved: `role="img"` + `<title>`/`<desc>` words summary, the visually-hidden per-row summary (now inside each `.pill-row`), `aria-hidden` escaped pills, severity colour via `scaleEntryColor`, per-row count, empty state, zero hydration. axe passes on default theme, desktop AND mobile.

The `setMembership` brick is self-contained: because a set-membership block is useless without a matrix to reference, the brick's section embeds BOTH a comparison-matrix block AND a set-membership block whose `sourceBlockId` is the embedded matrix's id, plus the companion severity + sources scales (reusing `comparisonMatrixScales`). So dropping the brick into a document yields a working UpSet immediately, and the cross-reference resolves to the in-section matrix.
