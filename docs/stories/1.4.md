# Story 1.4: Author Login

Status: Review

## Story

As the author,
I want to authenticate to my workspace,
So that only I can create and manage reports.

## Acceptance Criteria

**Given** author credentials configured at setup
**When** I log in with the correct password (argon2id at rest, AR6)
**Then** an author-realm session is created (signed, HttpOnly, SameSite cookie) and the workspace opens (FR35, NFR12)
**And** this story creates the sessions table migration (author realm)

**Given** a wrong password
**When** submitted repeatedly
**Then** responses are identical (no information leak) and rate limiting engages (NFR9, AR12)

**Given** an unauthenticated request to any workspace route
**When** received
**Then** it redirects to login; logout destroys the session

## Tasks / Subtasks

## Dev Notes

- Design authority for the login screen: UX spec tokens + "branded gateways" pattern (sober, wordmark in Cinzel allowed here).

### Completion Notes

- **Sessions (D4/D5)**: `sessions` table shared by both realms (realm check constraint; reader arrives in Epic 3). 256-bit random token in the cookie, SHA-256 hash at rest, **fixed 7-day expiry, no sliding renewal** (single known user; a hard lifetime bound is simpler to reason about). Expired rows are deleted on sight during validation. Session ids are UUIDv7 (architecture rule), generated app-side by `src/lib/server/db/ids.ts` (crypto.randomUUID is v4-only).
- **Signed cookie**: AC requires a signed cookie; the value is `<token>.<hmac-sha256(token, SESSION_SECRET)>` handled in `auth/cookies.ts` (`acta_author`, HttpOnly, SameSite=Lax, Path=/, Secure when ORIGIN is https). The HMAC rejects forged cookies (timingSafeEqual) before any DB lookup.
- **Uniform failure (NFR9)**: single password field means every attempt runs exactly one argon2 verification - a missing field verifies the empty string, so no dummy-hash branch is needed; the action returns the same `fail(401, 'Invalid credentials')` regardless of cause.
- **Rate limiting (AR12/D6)**: generic `TokenBucketLimiter` (capacity 5, refill 1/30s, 10k-key bound with full-bucket pruning) consumed by a `loginRateLimit` handle scoped to POST /login, keyed `ip:/login`. Placed innermost in `sequence(requestContext, securityHeaders, accessLog, loginRateLimit, authorRealm)` so the 429 still gets security headers and access logging. 429s are `application/problem+json` with Retry-After.
- **Realm resolution**: `authorRealm` handle populates `event.locals.authorSession` (typed in app.d.ts, `AuthorSession | null`) when the cookie verifies; an invalid/expired cookie is deleted so clients stop resending it. DB lookup only happens when the cookie is present.
- **problem.ts (AR4/D9)**: typed `AppError` (status, title, type, detail?, errors?[], headers?) + `problemResponse()` (RFC 9457 response, used by the rate-limit hook and by future /api/v1 endpoints) + `rateLimited()` + `errorPageShape()`. `handleError` now maps a thrown AppError to its problem fields and keeps the opaque 500 for everything else. Note for the /api/v1 story: SvelteKit's handleError cannot change the HTTP status of unexpected errors (always 500), so API endpoints must catch AppError and return `problemResponse(error)` themselves (or via a thin wrapper) - the hook mapping is the safety net, not the primary path.
- **Login UI**: first token slice in `src/app.css` (ink/stone/purple, spacing, radii, focus ring) per UX spec; centered card, "ACTA DIURNA" wordmark as styled text with a serif fallback stack (Cinzel ships self-hosted with Fontsource in 1.6 - the stack already names it, no external fetch). `/reports` is a real authenticated page (header with wordmark + Sign out form posting `?/logout`, empty state) that 1.5 turns into the reports list.
- **Playwright e2e deferred**: playwright.config.ts has had no webServer since 1.3 (preview needs a live Postgres for boot migrations). The login/logout flow was verified live via the compose run instead (see Debug Log). First e2e story must bring webServer + a database fixture; this story adds nothing to e2e.
- **QA iteration 1** (all findings applied):
  1. (High) Global failure-driven login brake: second token bucket `global:/login` (capacity 20, refill 1/10s) consumed ONLY on failed attempts in the login action; the hook `check()`s it (non-consuming) and returns the same 429 problem+json. Bounds total guessing when IPs collapse behind a proxy. Tests: brake engages across distinct callers, successful logins never consume it.
  2. (High) `maxTrackedKeys` is now a hard bound: after full-bucket pruning, the stalest entry (oldest `lastRefillMs`) is evicted before insert. Test rotates 50 keys past a bound of 3, map never exceeds it.
  3. (High) sessions.test.ts mock is hash-keyed and decodes drizzle `eq()` filters (Column + Param chunks): asserts validate/destroy query by `token_hash` = sha256(token); a raw-token or wrong-column regression now fails.
  4. (Med) `problemResponse` header passthrough restricted to allow-list `retry-after`/`www-authenticate` (case-insensitive); others dropped silently. Test covers Set-Cookie/CORS/custom rejection.
  5. (Med) Logout logic extracted to `src/lib/server/auth/logout.ts` `performLogout(cookies)`; both `(workspace)/+page.server.ts` and `(workspace)/reports/+page.server.ts` keep per-page actions that call it.
  6. (Med) `--color-ink-12/-25/-65` tokens added via color-mix; the four raw `rgb(28 27 46 / ...)` literals in login and reports pages replaced.
  7. (Med) accessLog enriches with `realm: 'author'` + sessionId (read after resolve, populated by innermost authorRealm); ordering-contract comment added on the sequence() call.
  8. (Med) handleError uses the `status` param for non-AppError: >= 500 stays opaque 'Internal Server Error', else SvelteKit's canonical message (e.g. 404 Not Found).
  9. (Med) `scripts/hash-password.ts` reads the password from a hidden stdin prompt by default (readline, echo suppressed via sink output on TTY); argv stays as fallback with a shell-history warning on stderr. Gotcha found while verifying: `rl.close()` emits 'close' synchronously, so the EOF fallback must not race the question callback - settle first, then close. Verified: piped stdin, EOF (clean usage error), argv fallback.
  10. (Low) WHY comment on ids.ts division-based byte extraction (JS bitwise ops truncate to 32 bits).
  11. (Low) `(workspace)/+page.svelte`: dropped the `resolve` ceremony. A plain href trips `svelte/no-navigation-without-resolve` (lint gate), so the never-rendered anchor was removed entirely instead - the comment-only component satisfies SvelteKit.
  12. (Low) password.test.ts malformed-hash env mutation wrapped in try/finally restore.
  13. (Low) architecture.md tree: `login/` recorded top-level with the realm framing (top-level = public realm: login, r/[token]; `(workspace)` = author realm).
- **For 1.5**: the guard lives in `(workspace)/+layout.server.ts` (redirect 303 /login when `locals.authorSession` is null) - new workspace routes inherit it by living in the group; read the session from `event.locals.authorSession` only (never re-validate); throw `AppError` from services and map with `problemResponse` in API surfaces; `getDb()` now carries the schema type, `db.query.sessions` is available; new tables follow the 1.4 pattern (schema.ts -> `drizzle-kit generate --name <x>` with DATABASE_URL set).
