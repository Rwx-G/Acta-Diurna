# Story 1.4: Author Login

Status: Approved

## Story

As the author,
I want to authenticate to my workspace,
So that only I can create and manage reports.

## Acceptance Criteria

**Given** author credentials configured at setup
**When** I log in with the correct password (argon2id at rest, AR6)
**Then** an author-realm session is created (signed, HttpOnly, SameSite cookie) and the workspace opens (FR35, NFR12)
**And** this story creates the sessions table migration (author realm)

**Given** a wrong password
**When** submitted repeatedly
**Then** responses are identical (no information leak) and rate limiting engages (NFR9, AR12)

**Given** an unauthenticated request to any workspace route
**When** received
**Then** it redirects to login; logout destroys the session

## Tasks / Subtasks

- [ ] sessions table migration (id, realm, hashed token, created/expires, metadata) - realm column ready for the reader realm (Epic 3)
- [ ] `src/lib/server/auth/`: argon2id password verify (author password hash provided via env at setup: AUTHOR_PASSWORD_HASH, plus a documented helper to generate it), session create/validate/destroy, cookie handling (signed, HttpOnly, SameSite=Lax, Secure behind proxy)
- [ ] In-memory token-bucket rate limiter (AR12) in `src/lib/server/auth/rate-limit.ts`, wired in hooks for the login endpoint; uniform error response (no user enumeration, constant-shape)
- [ ] `(workspace)` group layout guard: unauthenticated -> redirect to `/login`; login page (UI tier primitives, tokens); logout action
- [ ] AppError + problem-details hook mapping (`src/lib/server/problem.ts`) - first consumer is auth; same model serves everything after (AR4)
- [ ] Tests: session lifecycle, rate limiter behavior, guard redirects (Vitest); login/logout e2e (Playwright)

## Dev Notes

- Authority: architecture D4/D5/D6 (hand-rolled DB sessions, argon2id, in-memory bucket - no Redis, single process), patterns (two realms strictly separated - separate cookie names; only author realm implemented here, schema ready for reader).
- argon2: use the maintained `argon2` npm package (architecture-approved family); pin exact version.
- SESSION_SECRET from env signs cookies; never logged (pino redaction from 1.3).
- problem.ts is cross-cutting groundwork: build it properly here (typed AppError with status + errors[]; single mapping point in hooks.server.ts).
- Design authority for the login screen: UX spec tokens + "branded gateways" pattern (sober, wordmark in Cinzel allowed here).
