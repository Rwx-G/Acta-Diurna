# Story 9.3: Workspace "What Changed Since Last Issue" View

## Status

Review

## Story

As the author,
I want to see exactly what changed between this issue and the previous one before I publish or share,
So that I can sanity-check the refill and write an accurate summary without diffing by eye.

## Acceptance Criteria

**Given** a published issue with a published predecessor
**When** I open the "what changed" view in the workspace
**Then** I see the `SeriesDiff` rendered as a readable changelog: sections and blocks added / removed / moved, data-bound values that changed (old -> new), and prose that was rewritten, grouped by section and ordered by the document structure

**Given** the diff view
**When** a block changed in more than one dimension (e.g. moved AND its data changed)
**Then** every applicable verdict is shown for that block, not just the first, so the author sees the full picture

**Given** an issue with no published predecessor, or a substantial-drift pair
**When** I open the view
**Then** it shows the corresponding neutral state ("this is the first issue of the series" / "structure changed too much to compare block by block") rather than an empty or broken view

**Given** the view
**When** it renders
**Then** it is owner-scoped (only my own series and issues are reachable; a cross-author id is the neutral 404), shows no speaker notes or any author-private field, and surfaces the predecessor's `issue_label` / publish date as the comparison baseline label

## Dev Notes

### Surface (the decision)

- **A dedicated owner-scoped route, `/reports/[id]/changes`, not a panel inside the editor.** It mirrors the sibling author surfaces (`/present`, `/view`, `/share`): a workspace route behind the auth guard, scoped to the owner through the Epic 8 `resolveAuthorScope`, so the existing tenancy seam (a non-owner or unknown id is the same neutral 404) applies for free. A separate route also keeps the editor bundle untouched and the diff view independently linkable from the toolbar.
- **The view consumes the 9.2 engine through a thin composition service, `getSeriesDiffView`.** `diffSeriesIssue` (9.2) already returns the typed `SeriesDiff` under one `AuthorScope`. 9.3 adds only the comparison BASELINE LABEL (AC4): the predecessor's `issue_label` / publish date. Rather than widen the engine, the new service composes `diffSeriesIssue` with the predecessor's row from the owner-scoped ordered series (`listSeriesIssues`), so the baseline is resolved under the same scope and a cross-author predecessor is unreachable. The baseline is attached only to a computed `diff` (the neutral kinds have no meaningful baseline to label).

### Neutral states (rendered on `kind`, not special-cased in the loader)

- The loader passes the `SeriesDiff` through verbatim; the component switches on `kind`. `no-predecessor` with reason `first-issue` -> "this is the first issue of the series"; reason `predecessor-unpublished` -> a DISTINCT "the previous issue is not published yet" message (the two reasons the 9.2 engine already keeps apart); `substantial-drift` -> "structure changed too much to compare block by block". Each is an `EmptyState`, never an empty or broken page (AC3).
- A DRAFT issue (no published edition to diff) is gated BEFORE the diff: the loader reads the report, and an unpublished issue returns a `not-published` state the page renders as a publish-first prompt, so the 409 the diff would raise never reaches the UI. This matches the presenter route's publish-first gate.

### Every applicable verdict (AC2)

- A block's `BlockDiff` carries `change` (added/removed/moved/kept) plus the independent `dataChanged` / `contentChanged` booleans. The view renders ALL of them as tags: a block that moved AND whose data changed shows "Moved", "Data changed", and (if applicable) "Content changed". An unchanged `kept` block keeps its single "Unchanged" tag rather than vanishing, so the changelog reads as the full section structure, not only the deltas.

### Leak safety (the guarantee)

- **The view shows CHANGE FLAGS and section/block ids, titles, and types only - never a speaker note, never a prior-issue block body.** This is enforced by the engine, not by view discipline: `SeriesDiff` (9.2) is a typed structure of `{ id, type, change, dataChanged, contentChanged }` per block and `{ id, title, change, blocks }` per section. It carries no `notes` field and no block content, so the loader CANNOT serialize one - the heavy `document` / `published_document` columns never reach this seam (the diff reads them server-side to compute flags, then discards them). The baseline carries only the predecessor's cosmetic labels.
- The service test asserts this at the payload level: the serialized `getSeriesDiffView` result contains neither the prior nor the new prose, no `paragraphs`, and no `notes`. The component test asserts a note string placed in the surrounding scope is never echoed. The e2e asserts the predecessor's prior prose is absent from the rendered view DOM.
- `getSeriesDiffView` does NOT re-fetch any prior-issue content: it reuses `diffSeriesIssue`'s flags and only adds the predecessor's metadata row (`SeriesIssue` projection: id, title, status, predecessor, label, publish date, updated-at - no document columns). The "never fetch and show prior-issue content" constraint holds by construction.

### Accessibility / design system

- The view uses the shared workspace components (`PageHeader`, `EmptyState`) and design tokens. Verdict tags convey state by an explicit text label ("Added" / "Removed" / "Moved" / "Data changed"), not colour alone, so the changelog is readable without colour perception. The changelog is a labelled `region`; neutral states are `EmptyState` cards. Desktop workspace surface: the e2e mobile project skips it (the workspace is desktop-only).
