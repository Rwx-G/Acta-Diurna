# Story 10.4: Per-Block-Type Editing - Reporting and Rich Blocks

## Status

Review

## Story

As the author,
I want the Epic 7 reporting and rich blocks to be editable in the WYSIWYG editor,
So that comparison matrices, callouts, lists, timelines and the rest are authored visually, not hand-written JSON.

## Acceptance Criteria

**Given** a scale-driven block (comparison-matrix, set-membership, legend, chip-cluster, timeline)
**When** edited
**Then** scale and entry references are picked from the document's declared scales (never raw keys typed blind), a set-membership block picks its `sourceBlockId` from the document's comparison-matrix blocks, and an unknown or dangling reference is the actionable validation error naming the offending reference (FR2 parity) - the editor reuses the existing per-block editors for these

**Given** a content block (callout, code, card-grid, field-grid, list)
**When** edited
**Then** tone / icon / items / layout are edited in place through their existing editors, icon pickers offer only the curated registry names (Epic 7.6), and the preview renders the SSR result

**Given** a block whose authoring is genuinely complex (the comparison-matrix findings grid)
**When** scoped
**Then** the editor covers the structured findings editing the existing `ComparisonMatrixBlockEditor` already provides, and any deferred refinement (e.g. bulk paste of findings) is named explicitly here as deferred, not silently missing

**Given** any reporting/rich-block edit
**When** saved
**Then** it is the same validate-on-write path and the preview is the authoritative render - no block type has a side path

## Dev Notes

### This REFINES already-mounted rich sub-editors on the 10.1 seam - it is not a from-scratch build

The 1.5 editor already shipped per-block-type sub-editors for the ten Epic 7 reporting/rich blocks, dispatched by `BlockEditor` (`ComparisonMatrixBlockEditor`, `SetMembershipBlockEditor`, `LegendBlockEditor`, `ChipClusterBlockEditor`, `CalloutBlockEditor`, `CodeBlockEditor`, `CardGridBlockEditor`, `FieldGridBlockEditor`, `ListBlockEditor`, `TimelineBlockEditor`). Story 10.1 wired the debounced live preview + optimistic validation + validated save; 10.2 added the palette + structural editing; 10.3 brought the five core editors up to the AC and introduced the run-level text editor + the `RUN_MARKS` / `toggleRunMark` / `setRunLink` / `newRun` helpers. Story 10.4's job was to bring the rich editors up to their AC on the same seam.

What EXISTED vs what was REFINED, per rich type:

- **comparison-matrix** - existed: the full structured findings grid (category, label, severity from the severity scale, tag, per-source cells, treatment; severity / source scale refs from the declared scales). Refined: added finding REORDER (move up / down) and an explicit note that the Epic 11 `linkTo` is preserved (the editor mutates in place, never touches the field it does not surface). Scoped: bulk paste of findings deferred.
- **set-membership** - existed and unchanged: picks `sourceBlockId` from the document's comparison-matrix blocks (a select), plus an optional title. The dangling-ref check is the existing cross-reference pass.
- **legend** - existed and unchanged: picks `scaleRef` from the declared scales, plus an optional title.
- **chip-cluster** - existed and unchanged: picks `scaleRef` from the declared scales, then each chip's entry from that scale's entries.
- **timeline** - existed: per-milestone `status` ({ scaleRef, entry }) picked from the declared scales (the entry select reset to empty on a scale change so a stale entry cannot dangle), label, date, detail. Refined: the detail is now run-bearing (shared editor), and milestones reorder (move up / down).
- **callout** - existed: tone enum, icon registry, kicker. Refined: the body is now run-bearing (shared editor), replacing the flatten-on-edit textarea.
- **code** - existed and unchanged: language, escaped source (monospace, whitespace-preserving), optional annotations (note + optional line).
- **card-grid** - existed and unchanged: desktop column count, cards (icon registry / title / description), add / remove.
- **field-grid** - existed and unchanged: the grid / strip (meta-strip) layout variant, label / value items, add / remove.
- **list** - existed: ordered / unordered, item term. Refined: the optional description is now run-bearing (shared editor), added / removed as a whole.

### The run-marks reuse - one shared `ParagraphsEditor`, no freeform HTML

The four run-bearing surfaces (text block body, callout body, list-item description, timeline-milestone detail) edit the SAME `Paragraph[]` shape. Rather than copy the 10.3 run markup into each editor, it is extracted to one `ParagraphsEditor.svelte` that the text block delegates to (no field prefix, the bare "Paragraph N" accessible-name scheme kept byte-stable) and the three rich editors mount with a `label` prefix (e.g. "Callout body") so several run-bearing fields on one block stay distinguishable. The only formatting path is the boolean mark toggles (`bold` / `italic` / `code`) and the http(s) `link` href - the exact `inlineRunSchema` vocabulary - so a run produced here is always a valid schema run, never arbitrary markup (a component test toggles a mark and re-validates the document, another stores HTML-looking text as a literal string; the e2e toggles bold on a callout body and asserts the preview renders a `<strong>`).

### The scale-driven scaleRef-from-declared-scales approach, and how a dangling ref is caught

A scale-driven editor never offers a free text input for a scale / entry / source ref: it offers a `<select>` of the document's DECLARED scales (threaded down from `ReportEditor` as `scales` / `matrixBlocks`), the entry options resolved from the chosen scale via `resolveScaleRef`. So the editor cannot CREATE a dangling ref by typing one. A dangling ref still arises two legitimate ways - a scale referenced by a block is later removed from the document, or a freshly-added scale-driven block's starter ref is empty (not slug-valid) - and BOTH are caught by the existing document-level `validateScaleReferences` cross-reference pass: it walks the blocks, resolves each ref against `document.scales` (and a set-membership `sourceBlockId` against the comparison-matrix block ids), and emits a `{ path, message, hint }` naming the offending ref. That issue is the optimistic inline guidance (the client runs the SAME `documentSchemaV1` including the cross-reference passes) and, on save, the authoritative server 422 (FR2 parity). The component tests pin the 422 path for a dangling legend `scaleRef`, a chip entry, and a set-membership `sourceBlockId`; the e2e shows the inline error on a freshly-added scale-driven block whose starter ref is unresolved.

### The matrix-grid scoping decision

The comparison-matrix is the most complex rich block. The 10.4 deliverable is the STRUCTURED per-finding authoring (add / remove / edit findings and sources, set cells, the scale refs) the existing editor already provides, plus finding reorder added here. Bulk paste of findings (pasting a tabular grid of findings at once) is explicitly DEFERRED - it is a productivity refinement, not the core authoring, and is named here rather than silently missing. The per-source cells are keyed by the sources-scale entry keys and rendered one row per declared entry (the render tier iterates the scale order, not the record's own key order), so the editor surfaces exactly the columns the scale declares; there is no separate "add source" affordance because a source IS a sources-scale entry.

### Every editor reuses the 10.1 validated-save seam

No editor was given a save path. Each field mutation calls the `onEdit()` prop threaded down from `ReportEditor` (`BlockEditor` -> per-type editor), which sets `dirty` and schedules the debounced autosave; the live preview and optimistic validation both read the same debounced `settledSnapshot`. The save serializes `$state.snapshot(doc)` and posts it through `?/save` -> `updateReportDocument` (validate-on-write) with `expectedUpdatedAt`. So an invalid field is the optimistic inline guidance and then the authoritative server 422 - never a half-saved document.

### Reader-budget unchanged, schema unchanged

These editors are mounted only on the workspace edit route, behind the author cookie. `pnpm reader:budget` is byte-identical at 75.9 KB / 200 KB and `pnpm schema:export` shows no diff: 10.4 edits the SAME schema shapes the catalogue already defines, adding no block type and no field.

### Seams for 10.5, 10.6, 10.7

- **10.5 (binding from the editor):** untouched. The rich blocks edited here are author-written structured content (the matrix findings are NOT routed through the 2.4 flat-CSV binding path; the block has no `binding` field), so this story does not surface `bind` / `rebind` / `remap`. The bindable core editors (table / chart / kpi) already embed `BindingEditor`; 10.5 surfaces the existing binding actions at the block.
- **10.6 (audience-aware preview, tags, speaker notes):** the shared `BlockEditor` frame already mounts the `AudiencePicker` per block; 10.6 adds the level-switched preview and the section speaker notes. Untouched here.
- **10.7 (autosave / undo-redo / conflict / publish):** the single `scheduleSave` debounce, the `expectedUpdatedAt` concurrency token, and the publish / unpublish lifecycle are already wired in `ReportEditor`; 10.7 adds the undo / redo history and the explicit autosave UX. Untouched here.

### QA remediation (2026-06-15)

Addressed the 3-agent QA audit findings on the rich/reporting editors; no AC change, no schema change, reader budget unchanged.

1. **Index-keyed reorderable `{#each}` -> keyed by the bound OBJECT REFERENCE.** The matrix findings, the ParagraphsEditor paragraphs AND runs, the timeline milestones and the list items now key their `{#each}` by the item object, not the index. `moveItem` is an in-place adjacent swap that preserves object identity, so a reorder MOVES the existing subtree to its new slot instead of destroy+recreating every row whose index shifted (the O(findings*sources) / O(paragraphs*runs) churn the audit flagged). A component test captures a finding's label node, moves it, and asserts the SAME node is reused at the new position (no remount). The chip-cluster entries stay index-keyed: they are primitive strings with no stable reference identity (and may repeat), so an object key does not apply.
2. **Matrix scale-change now resets stale finding refs.** Changing `severityScale` resets every `finding.severity = ''`; changing `sourceScale` clears every `finding.sources = {}`. Previously the old-scale keys lingered invisibly until the save 422. Mirrors the timeline's existing `milestone.status.entry = ''` reset. Two component tests assert the severity and the source cells clear on a scale change.
3. **Run-link URL input guarded against the Epic 11 `linkTo` mutual-exclusion 422.** A run carrying an internal `linkTo` now disables its URL input (with an "Internal link set" note), and `setRunLink` is a no-op while `linkTo` is present (defence in depth). The editor can no longer author the conflicting `link`+`linkTo` state it could not then clear. A component test asserts the URL input is disabled on a `linkTo`-bearing run; a unit test asserts the `setRunLink` no-op.
4. **`TREATMENT_STATUSES` now a `{ value, label }[]`** rendering `Action` / `Deferred` (was the raw `action` / `deferred` enum text), mirroring `SOURCE_STATES`. A component test asserts the human option labels.
5. **`form-fields.css` extraction finished.** The local `.field-label` + `input, select` base resets were removed from the Callout / ChipCluster / Legend / SetMembership / List / Timeline / ComparisonMatrix editors so `form-fields.css` is authoritative (it absorbed the `font-weight: 400` / `line-height: 1.5` / `min-width: 0` the label-nested inputs need). The 15-line `.sr-only` clip block, verbatim-duplicated across ~6 editors, was extracted to a new `sr-only.css` imported by the workspace layout, scoped under `.block-card`; the accessible name is the span's DOM text, so an editor mounted outside the layout in a component test stays accessible (the rule only moves the text off-screen). Reader budget unaffected (CSS is workspace-only, excluded from NFR3).
6. **Timeline `resolveScaleRef` lifted out of the render loop.** The milestone row is now a child component (`MilestoneRow.svelte`) declaring `const entryOptions = $derived(resolveScaleRef(...))`, so the lookup memoizes per milestone and re-runs only on a scaleRef/scales change, not on every label/date keystroke (was a `{@const}` re-evaluated O(milestones*scales) per keystroke).
7. **Cheap fold-ins.** Inlined the single-use `addFinding()` at its one call site (consistency with the other editors); removed the redundant `aria-label` on the two matrix scale `<select>`s already wrapped in a `<label>`.

Deferred as debt (logged in Dev Notes, not fixed here): `scales` threaded live (`scales={doc.scales}`) vs the debounced `settledSnapshot` model - no scales-editing UI exists, `doc.scales` never mutates on the hot path today; the `ScaleHint` "No declared scales" copy duplication - extract when a 5th scale-driven block lands; the `scaleOptions ??
