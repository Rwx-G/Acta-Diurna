# Story 2.1: Compose a Skeleton from Template Bricks

Status: Done

## Story

As the author,
I want to compose a report structure from provided template bricks,
So that I never start a recurring report from a blank page.

## Acceptance Criteria

**Given** the built-in brick library (preconfigured section and block presets: cover, summary, data table, chart section, KPI row, annex)
**When** I assemble bricks into a structure in the workspace
**Then** the resulting skeleton is a valid schema-v1 document structure with placeholder bindings (FR8)

**Given** an assembled structure
**When** previewed
**Then** it renders with the default theme and placeholder content

**Given** an invalid structure (e.g. an empty section)
**When** I save
**Then** save is blocked with an inline actionable message at the offending element
**And** the composer follows UX Flow A (three-zone composer) in `ux-design-specification.md`

## Tasks / Subtasks

- [x] Brick library: a set of typed presets in `src/lib/bricks/` (isomorphic, schema-typed) - cover, summary, data table, chart section, KPI row, annex - each producing a valid schema-v1 section/block fragment with placeholder bindings (named expected fields, no data yet)
- [x] Three-zone composer per UX Flow A: left brick library (BrickCard with preview), center StructureTree (ordered sections/blocks, add via click, reorder, inline rename, remove), right LivePreview (the real renderer, scroll mode embedded)
- [x] Compose produces a valid DocumentV1 structure (validate via the schema package); invalid structure (empty section, no blocks) blocked at save with inline message at the offending element (reuse 1.5 error rendering)
- [x] Reuse the render tier for preview (LivePreview, identical renderer); tolerate transiently-invalid composition gracefully
- [x] Tests: brick library produces valid fragments (each preset validates); composer state operations (add/remove/reorder); invalid-structure save block; a browser component test for the BrickCard -> StructureTree add flow

## Dev Notes

- This closes the tracked UX gap (skeleton composition). Authority: ux-design-specification.md UX Flow A + Component Strategy (BrickCard, StructureTree, BlockInspector, LivePreview), architecture (schema sacred, render purity, routes thin).
- A skeleton IS a DocumentV1 structure with placeholder bindings - no new schema. Persistence is 2.2; this story builds the composer + bricks producing the in-memory/draft structure.
- Reuse 1.5 editor primitives where sensible; the composer is the structure-first sibling of the block editor. Coordinate component reuse (StructureTree may generalize the 1.5 section/block list) - keep DRY but do not over-abstract.
- Binding placeholders: bricks declare `binding.fields` (expected field names+types) with no dataSetId (data arrives in 2.4). This is the per-field expectation the 2.5 resolver maps onto block slots.
- Bricks live in `src/lib/bricks/` (isomorphic, schema-only imports - the ESLint schema-boundary guard family applies if placed under schema; bricks may import schema types).

## Dev Agent Record

### Debug Log

- Schema input vs output side: `validateDocument` returns the OUTPUT type (`DocumentV1`, defaults applied - e.g. `table.options.stickyHeader` becomes a required boolean), but the composer's in-memory draft and the brick factories are the INPUT side. `svelte-check` rejected `Section` (output) factories assembled into `DocumentV1Input['sections']`. Resolved by exporting a `SkeletonSection = DocumentV1Input['sections'][number]` alias from `$lib/bricks` and typing every factory, `appendBrick`, and `StructureTree` on it - the composer works in the producer shape throughout, validation crosses to the output side only inside `saveSkeleton`.
- `blockSummary` narrowing: `block.binding` exists on table/chart/kpi but not text/image; an `else` after the `text` branch still included `image` (no `binding`). Narrowed `image` explicitly before the binding branch.
- Ids: used `crypto.randomUUID()` (the same source the 1.5 editor documents for document-internal slug-valid anchors), not a uuidv7 package - the schema id rule is the slug pattern, which a lowercase UUID satisfies, and no uuidv7 dependency exists (none added, per the no-new-deps constraint).
- Reader budget unaffected (62.9 KB): the composer is workspace-only and never enters the reader-path import closure.
- Gates: `pnpm lint` exit 0 (2 files needed `prettier --write`, then clean); `pnpm check` 908 files, 0 errors / 0 warnings; `pnpm test` 306 unit tests passed (39 files), +53 over 1.6's 253; `pnpm build` adapter-node clean; `pnpm reader:budget` 62.9 KB (< 200 KB); `pnpm test:e2e` 17 passed (Docker 29.5.2 testcontainer + seeded fixture) - the existing reader/publish suites, unchanged by this story.
- Not live-checked in compose: the form-action wiring (`?/save` -> `saveSkeleton`) was not exercised through a real authenticated workspace session (would need the AUTHOR_PASSWORD_HASH + compose dance from 1.5/1.6). The seam is covered by `saveSkeleton` unit tests (valid + 422 empty-section + 422 empty-title) and the action is a thin `validateDocument`-via-service wrapper; the BrickCard -> StructureTree flow is covered by browser component tests. ### Completion Notes

- **Brick library** (`src/lib/bricks/index.ts`, isomorphic, imports only schema types): six typed presets each a `factory()` returning a fresh schema-valid `SkeletonSection` with `crypto.randomUUID()` ids and real authoring-prompt text (no lorem). `cover` (text title/standfirst), `summary` (summary-audience text), `dataTable` (table + placeholder columns + `binding.fields` item/status/count), `chartSection` (line chart + binding period/value + axis/legend labels), `kpiRow` (kpi + binding label/value/trend), `annex` (annex-flagged technical-audience text). Data-bound bricks declare `binding.fields` with NO `dataSetId` (data arrives Epic 2). `BRICKS` registry (id, label, description, factory) in display order; `getBrick(id)` lookup.
- **Composer route** `(workspace)/skeletons/compose`: `+page.svelte` (thin) -> `SkeletonComposer.svelte` (state owner, save form via `use:enhance`) wiring three zones per UX Flow A - left `BrickLibrary` (BrickCard list, click appends), center `StructureTree` (ordered sections/blocks: reorder up/down, inline section rename, remove section/block, block content summarised not edited - structure-first), right `LivePreview` (the 1.6 component, identical renderer, tolerant `toPreviewView`). Opens with a starter Cover brick (never a blank structure). Library collapses to a grid above the structure below the 1280px composer breakpoint (UX responsive note).
- **Reuse from 1.5 (no duplication)**: `compose-state.ts` re-exports `moveItem`, `groupErrorsByLocation`, `humanizePath`, `EditorIssue`, `ErrorsByKey` from the edit editor-state; `StructureTree`/`SkeletonComposer` import the 1.5 `IssueList.svelte` directly; the LivePreview is the 1.6 `[id]/preview/LivePreview.svelte`. No 1.5 component was modified, so the report editor and its tests stay green (verified: full 306-test run). The only new abstraction is `SkeletonSection` (a type alias) and `appendBrick` (a three-line helper) - no premature generalization.
- **Validation + inline errors**: composing builds a `DocumentV1Input`; `saveSkeleton` (`src/lib/server/skeletons/skeletons.ts`) validates via `validateDocument` and throws a 422 `AppError` carrying `errors[]` on failure. The composer maps those via the reused `groupErrorsByLocation` against the submitted snapshot so an empty section (zero blocks) or empty title renders its message inline at the offending section element (reused `IssueList`), never a toast - matching the 1.5 error-rendering pattern and UX Flow A's error path.
- **QA iteration 1 (2026-06-12)**: addressed the review findings.
  - High: removed the dead `saveFormElement` `$state` + its `bind:this` in `SkeletonComposer.svelte` (nothing read it).
  - Medium: the brick binding presets (`TABLE_BINDING`/`CHART_BINDING`/`KPI_BINDING`) were aliased by reference into every factory result, so a downstream draft mutation would corrupt the module singleton; each factory now returns a deep copy via `cloneBinding` (spread + per-field clone). Test asserts two calls return non-aliased bindings and a mutation does not leak.
  - Medium: extracted the cross-editor primitives (`moveItem`, `groupErrorsByLocation`, `humanizePath`, `EditorIssue`/`ErrorsByKey`) into a new `$lib/editor` module. Both the 1.5 editor (`editor-state.ts`) and the composer (`compose-state.ts`) now import from the stable `$lib` path; the cross-route relative re-export is gone. `editor-state.ts` re-exports the moved symbols so its existing consumers (IssueList, ReportEditor, SectionEditor, BlockEditor - kept in place as components) need no change. The 1.5 report editor and its full test suite stay green.
  - Medium: both save actions (`skeletons/compose` and `reports/[id]/edit`) now cap `raw.length` against the shared `MAX_DOCUMENT_BYTES = 1_000_000` (in `$lib/editor`) and return `fail(413)` before `JSON.parse`. 413 path tested on the report edit action.
  - Low: `StructureTree.blockSummary` is now an exhaustive `switch` over the input-side block union with explicit `table`/`chart`/`kpi` handling and a `satisfies never` default, so a future block type cannot fall through silently.
  - Low: moved the test-only `ComposeHarness.svelte` + `compose.svelte.test.ts` into a colocated `__tests__/` dir so the harness no longer ships in the route bundle (the browser-test include glob still reaches it; the moved test runs green).
  - Low: extracted `removeSection(sections, index)` into `compose-state.ts`, wired `StructureTree`'s section-remove button to it, and re-pointed the previously-trivial test at it (it now tests app logic + the out-of-bounds guard, not raw `splice`).
  - Gates after iter 1: `pnpm lint` clean, `pnpm check` 909 files 0 errors, `pnpm test` 308 passed (39 files), `pnpm build` clean, `pnpm reader:budget` 62.9 KB, `pnpm test:e2e` 17 passed (Docker 29.5.2).
- **Save seam for 2.2**: `saveSkeleton(structureInput)` is the documented persistence seam. Today it validates and returns `{ name, structure }` (name = document title; structure = the validated `DocumentV1`). Story 2.2 inserts `result.document` into a `skeletons` table at the marked comment and returns the row id - no placeholder/TODO, a real validated round-trip with a clear extension point. The action returns `{ savedName }` on success.
