# Story 8.6: Mode-Aware Login and Workspace UX, plus Operator Docs

## Status

Done

## Story

As an author and as an operator,
I want the UI and the docs to reflect the active mode,
So that signing in and operating the instance are clear in both single and multi mode.

## Acceptance Criteria

**Given** the active mode
**When** the login screen renders
**Then** SINGLE mode shows the password field and MULTI mode shows the email (magic-link) field - never both, driven by the one mode resolver

**Given** MULTI mode
**When** an author is in the workspace
**Then** they see ONLY their own reports / data sets / shares / tokens, and their identity (email) is surfaced; nothing reveals another author's existence or resources

**Given** the operator
**When** they read the deployment docs
**Then** `docs/ops/deployment.md` documents both modes, the env vars (`AUTHOR_EMAIL_DOMAIN`, `INITIAL_OWNER_EMAIL`, `READER_EMAIL_DOMAINS`, the SMTP block), the fail-fast boot rules, the bare-relay support, the CLI SMTP test, and the lockout/recovery procedure (no password in multi mode -> fix/remove SMTP env and restart)

**Given** the whole epic
**When** audited
**Then** the auth-realm separation, the tenancy filtering (no IDOR), the enumeration-safety, and the no-lockout-by-misconfig guarantees are verified and test-backed

## Dev Notes

- The field/action split was already correct from story 8.3; this story only refined the copy and added the email-field hint. The single-mode password form is untouched.
- Author identity is surfaced from the layout server load (`(workspace)/+layout.server.ts`), the one place that already guards the realm. It calls `authorDisplayEmail(authorSession.authorId)` only when `isMultiAuthor()` and the session carries a real author id (multi-mode magic-link sessions do; single-mode password sessions carry `authorId: null`).
- `authorDisplayEmail` hides the implicit author's sentinel email (`SINGLE_AUTHOR_EMAIL`), so even a defensive lookup of the implicit author returns null - single mode never shows an identity.
- Tenancy (own-resources-only) is enforced at the data layer by story 8.2; this story adds no new filtering, only the identity surface. There is no list/affordance that could leak another author's existence.
- The `.env.example` file is fenced by the secrets hook and could not be read; the env var shapes and defaults documented in `deployment.md` were taken from `src/lib/server/env.ts` (authoritative).
