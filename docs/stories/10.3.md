# Story 10.3: Per-Block-Type Editing - Core Blocks (Text, Table, Chart, KPI, Image)

## Status

Review

## Story

As the author,
I want each core block to have its own editing affordance wired to the live preview,
So that I edit a table as a grid, a chart as series config, and text as inline-formatted runs, not as raw JSON.

## Acceptance Criteria

**Given** a text block
**When** edited
**Then** the existing inline-run vocabulary (the marks the schema defines: bold / inline-code / link) is editable in place and the preview reflects it; the editor introduces no freeform HTML and pasted HTML is never trusted into the document (renderer-purity holds)

**Given** a table block
**When** edited
**Then** columns and rows are edited as a grid (add / remove / reorder column and row), and a scale-formatted column (`scaleRef`, Epic 7.5) is editable as such; an out-of-scale cell value is the actionable validation error naming the row and column

**Given** a chart or kpi block
**When** edited
**Then** chart series / kind and kpi items are edited through their existing per-block editors, the preview re-renders the SSR chart from the in-edit config, and invalid config surfaces inline

**Given** an image block
**When** edited
**Then** the asset reference and alt text are edited in place (no new asset-upload pipeline - it reuses what ingestion provides), and a missing alt is the accessibility-relevant validation error at the block

**Given** any core-block edit
**When** the author saves
**Then** the write is the single validate-on-write path (10.1), and the preview is the authoritative reader render of the result

## Dev Notes

### This REFINES the 1.5 per-type editors on the 10.1 seam - it is not a from-scratch build

The 1.5 editor already shipped per-block-type sub-editors (`TextBlockEditor`, `TableBlockEditor`, `ChartBlockEditor`, `KpiBlockEditor`, `ImageBlockEditor`, dispatched by `BlockEditor`). Story 10.1 wired the debounced live preview + optimistic validation + validated save; 10.2 added the palette + structural editing and the block/section focus management. Story 10.3's job was to bring the five CORE per-type editors up to the AC: complete the missing affordances and replace the one genuinely sub-AC editor (text).

What EXISTED vs what was REFINED, per core type:

- **TEXT** - existed: a textarea per paragraph that read the concatenated run text and, on edit, REPLACED the paragraph with one unformatted run (`[{ text }]`), discarding any marks (the explicit 1.5 MVP trade-off documented on `paragraphText`). Refined: a run-level editor with the schema's mark toggles and link field, so bold / italic / inline-code / link are editable in place and the preview reflects them - the 10.3 headline gap. No contenteditable, no HTML.
- **TABLE** - existed: column key/label/`scaleRef` edit with row-value migration on rename, static cell edit, column/row add+remove. Refined: added column and row REORDER (the missing "reorder" half of the AC).
- **CHART** - existed: kind, series name, points (x, y with finite guard), add/remove. Refined: added the optional axis/legend label fields (in the schema, not previously surfaced) and series reorder.
- **KPI** - existed: label, value, unit, trend, add/remove. Refined: added item reorder. (Already met the field AC; reorder rounds it out.)
- **IMAGE** - existed: a DISABLED `assetId` display plus editable alt + caption. Refined: made the asset reference editable in place (no new upload pipeline) so the author can point at an uploaded asset; alt stays required.

### The text inline-marks approach - no freeform HTML, by construction

The only formatting path is the boolean mark toggles (`bold` / `italic` / `code`) and the http(s) `link` href - the exact vocabulary `inlineRunSchema` defines and `InlineRuns.svelte` renders. A run's text is a plain `<input value>`; whatever the author types (including `<b>...`) is stored as the literal string and rendered through Svelte text interpolation, which escapes (the existing `InlineRuns` XSS tests pin this). There is no contenteditable, no paste-to-HTML, no `{@html}` anywhere in the path. So a run produced by this editor is always a valid schema run, never arbitrary markup - confirmed by the component test that toggles a mark and re-validates the document, and by the e2e that toggles bold and asserts the preview renders a `<strong>`, not injected HTML.

### Every editor reuses the 10.1 validated-save seam

No editor was given a save path. Each field mutation calls the `onEdit()` prop threaded down from `ReportEditor` (`BlockEditor` -> per-type editor), which sets `dirty` and schedules the debounced autosave; the live preview and optimistic validation both read the same debounced `settledSnapshot`. The save serializes `$state.snapshot(doc)` and posts it through `?/save` -> `updateReportDocument` (validate-on-write) with `expectedUpdatedAt` for optimistic concurrency. So an invalid field is the optimistic inline guidance (off the settled snapshot) and then the authoritative server 422 - never a half-saved document.

### Reader-budget unchanged, schema unchanged

These editors are mounted only on the workspace edit route, behind the author cookie. They import `$lib/schema` types and the `editor-state` helpers (which import the schema OBJECT for optimistic validation, never the server validate machinery - the 10.1 reader-purity boundary). `pnpm reader:budget` is byte-identical at 75.8 KB / 200 KB and `pnpm schema:export` shows no diff: 10.3 edits the SAME schema shapes the catalogue already defines, adding no block type and no field.

### Seams for 10.4 and 10.5

- **10.4 (reporting/rich blocks):** the same `BlockEditor` dispatcher already mounts the eight rich per-type editors (`ComparisonMatrixBlockEditor`, `LegendBlockEditor`, `SetMembershipBlockEditor`, `ChipClusterBlockEditor`, `CalloutBlockEditor`, `CodeBlockEditor`, `CardGridBlockEditor`, `ListBlockEditor`, `TimelineBlockEditor`, `FieldGridBlockEditor`); 10.4 refines those to their AC on this same seam. The shared reorder pattern (`moveItem` + per-row move controls) and the run-mark helpers (`RUN_MARKS` / `toggleRunMark` / `setRunLink`, reusable by callout/list/timeline run editing) are the primitives 10.4 builds on.
- **10.5 (binding from the editor):** the bindable core editors (table / chart / kpi) already embed `BindingEditor` (`bind:binding`). 10.5 surfaces the existing `bind` / `rebind` / `remap` actions and the per-block diagnostic chips at the block; this story does NOT touch binding (the static-data shape only), leaving that seam clean.

### Latent chart-geometry note (out of scope, surfaced by the e2e)

A chart with a SINGLE data point is a degenerate zero-range axis: the render-tier `ChartBlock` keys its axis ticks by value (`{#each geometry.yTicks as tick (tick.value)}`), and a zero-range domain can yield duplicate tick values, tripping Svelte's `each_key_duplicate` on hydration. This is a pre-existing render-tier edge (Epic 7 chart geometry), not a 10.3 editing concern; the e2e gives its chart two points to stay on the supported path. Flagged here for a future chart-geometry hardening pass (dedupe degenerate ticks), not fixed in this story.

### QA remediation (2026-06-15)

Seven findings from the three-agent QA audit, fixed on the same seam (no new dependency, no schema-shape change, no new write path):

1. **Table column-key collision (silent data loss, two-layer fix).** SCHEMA: a new `.superRefine` on the table block schema rejects duplicate column keys with an actionable RFC 9457 issue at `columns[n].key` naming the colliding key, so a dup-key document is a 422 on save on every write path, never silently persisted (`requireStaticDataOrBinding` still chains first). EDITOR: "Add column" now mints a collision-free `crypto.randomUUID()` key (the old `column-${length + 1}` counter reused a key freed by an earlier delete) while keeping the friendly `Column N` label; `renameColumnKey` no-ops and surfaces an inline `role="alert"` when the target key already belongs to another column, rather than overwriting that column's row cells.
2. **`RunMark` is now schema-derived.** `type RunMark = Extract<keyof InlineRun, 'bold' | 'italic' | 'code'>` and `RUN_MARKS = [...] as const satisfies ReadonlyArray<RunMark>`, so renaming/removing a mark in `inlineRunSchema` is a compile error (the literal type the story claimed but did not have).
3. **`errorsByKey` indexes the settled snapshot (perf).** The O(sections x blocks) `groupErrorsByLocation` ran against the live `doc` on every keystroke; the normal-flow branch now indexes `settledSnapshot` (the failed-save branch keeps the submitted doc), so placement runs once per 200 ms settle. Block ids are stable across the settle, so inline errors still place correctly.
4. **Chart axis-tick `each_key_duplicate` crash (render tier).** `ChartBlock` keyed the y/x tick `{#each}` by `tick.value`; a flat/tiny domain rounds several ticks to the same `formatTickValue` string, tripping `each_key_duplicate` on hydration. Re-keyed by position index (positionally stable). Renderer stays pure (escaped, no `{@html}`); a render test covers a flat-domain chart whose ticks all format to "0.0".
5. **Label-in-name (WCAG 2.5.3).** The run/column/row/series/kpi-item and block move/remove controls now carry the full descriptive name in a `.sr-only` span with the visible glyph `aria-hidden`, so the accessible name is self-contained and ordered. The pattern the 10.4 rich editors inherit. `.sr-only` is component-scoped in each editor (not only in the shared CSS) so it holds when an editor mounts outside the workspace layout (component tests).
6. **CSS duplication.** `.field-label` and the input/select base reset are extracted to a workspace-scoped `form-fields.css` (imported by the workspace layout, scoped under `.block-card`); each core editor keeps only its component-specific overrides. CSS is excluded from the NFR3 JS budget and the import never reaches a reader route, so the reader bundle is unaffected.
7. **Folded in:** a `toggleRunMark(run, 'italic')` marks test; a min-column disabled-boundary test; a UUID-shaped placeholder + `aria-describedby` on the image asset-reference field linking its existing note; an adjacent-swap-only invariant comment near the index-keyed reorder `{#each}`.

Deferred (logged, not done): the `previewSnapshot = settledSnapshot` alias (10.6) and the `scaleOptions ?? []` allocation (negligible) - left as-is per the audit's own guidance.

Gates after remediation (local, no CI): `pnpm test` 1966 passed / 169 files, 0 failed (incl. table-dup-key, chart-tick, marks-italic, disabled-boundary tests); `pnpm build && pnpm test:e2e` 138 passed, 37 skipped, 0 failed (editor + reader axe clean); `pnpm test:e2e:multi` 11 passed, 0 failed; `pnpm lint` clean; `pnpm check` 0 errors / 0 warnings; `pnpm reader:budget` 75.9 KB / 200 KB (the +0.1 KB is the index-keyed chart-tick render fix, a negligible render-tier delta); `pnpm schema:export` no diff (the dup-key refine adds no JSON-Schema node).
