# Story 2.5: Automatic Rebinding & Binding Diagnostics

Status: Review

## Story

As the author,
I want fresh data to rebind automatically and mismatches to be diagnosed precisely,
So that the weekly cycle is "inject, glance, share" - even when an export format drifts.

## Acceptance Criteria

**Given** a report with bound blocks
**When** a fresh data set matching the existing bindings is injected
**Then** all bound blocks re-render with the new data, without manual rebinding (FR14)

**Given** a fresh data set with a renamed or missing field
**When** binding resolves
**Then** the report is flagged with an actionable diagnostic naming the block, the expected field, and the closest candidate (FR15)
**And** I can remap the binding from the diagnostic and re-render
**And** binding states and diagnostics follow UX Flow B in `ux-design-specification.md`

## Tasks / Subtasks

- [x] Automatic rebinding: injecting a fresh data set whose fields match existing block bindings re-resolves every bound block with the new data, no manual re-mapping (FR14). Match by the binding contract from 2.4.
- [x] Binding diagnostics: when a fresh data set has a renamed/missing field, produce an actionable diagnostic per affected block - name the block, the expected field, and the closest candidate (string-distance match against available fields). Problem-details shaped, consistent with the schema error model.
- [x] Remap-in-place: from a diagnostic, the author maps the expected field to an available field and re-renders; the remap persists in the document binding.
- [x] Binding state surface per UX Flow B: per-block status chips (green bound/fresh, amber drifted -> diagnostic + closest-match remap, red unresolved) + a header BindingSummary aggregate ("N bindings - all green"). Components: BindingChip, BindingSummary, DiagnosticPanel.
- [x] Tests: matching fresh data rebinds all blocks (FR14); renamed field -> diagnostic with correct closest candidate; missing field -> diagnostic; remap persists and re-renders; binding summary aggregation; the closest-match algorithm (edge cases: no candidate, multiple equidistant)

## Dev Notes

## Dev Agent Record

### Debug Log

- CSV cells stay strings through `resolveTable` (`toCell` keeps a string a string), so a rebound `count` column holds `'4'`, not `4`. Tests assert the raw string form; only chart `y` and kpi `value` paths coerce to number.
- `closestField` is pure Levenshtein, so the UX-spec illustration "severity -> criticality" is NOT what minimal edit distance picks when an unrelated shorter field is present (e.g. `count` at distance 5 beats `criticality` at distance 8). The tests use realistic close renames (case change, one-char drift) where the closest IS the intended field; the contract is "minimal edit distance, first-index tie-break", documented on `distance.ts`, not "semantic match".
- Auto-rebind needs NO extra state: the slot mapping is recovered straight from `block.binding.fields[].slot` (keyed by field name) via `recoverSlotMapping`, exactly as the 2.4 Completion Notes promised. `buildBinding` then rebuilds the binding from the FRESH data set's fields applying that mapping, so all originally-slotted fields still present in the fresh data keep their slots.
- `rebindReport` persists only when at least one block re-resolved (`rebound.length > 0`). A refill that matches nothing must not churn `updatedAt` nor risk a needless 409 on a published report when there was no work.
- `remapField` rewrites the binding field NAME to the available field while preserving its slot (the author's role intent), then re-resolves; because `buildBinding` maps over the fresh data set's fields, the recovered mapping must be re-keyed under the NEW name (delete old key, add new) before applying.
- Playwright strict-mode bit twice in the refill e2e: "all green" matches both the BindingSummary `<strong>` and the success toast `<p>`, and `<code>count</code>` matches the expected/closest/`counts`-substring codes. Scoped to `p[role="status"][aria-live]` (the summary is the only live region) and `code.closest` respectively.

### Completion Notes

**Scope: Review.** Automatic rebinding (FR14), binding diagnostics with closest-match (FR15), remap-in-place, and the full BindingChip/BindingSummary/DiagnosticPanel surface ship here. No new dependency: the string distance is a hand-written Levenshtein (`distance.ts`, ~15 lines of DP).

**Closest-match algorithm + tie-break (the load-bearing logic, `distance.ts`).** Two-row Levenshtein (insert/delete/substitute, cost 1), case-sensitive. `closestField(expected, available)` returns `{ candidate, distance }`. Tie-break, deterministic and documented: (1) lowest edit distance wins, so an exact match (distance 0) always beats a near match; (2) on equal distance the candidate appearing FIRST in `available` wins (lowest index) - `available` is the data set's declared field order, so the pick is stable and meaningful. Edge cases: empty `available` -> `{ candidate: null, distance: Infinity }` (rendered as "no field available to remap onto"); multiple equidistant -> the lowest-index one (strict `<` preserves the first). Thoroughly unit-tested incl. exact-beats-near and the strictly-closer-later-candidate case.

**Auto-rebind recovers the slot mapping from the persisted binding - confirmed no extra state.** `recoverSlotMapping(binding)` reads each slotted `binding.fields[].slot`, keyed by field name; that mapping plus the fresh data set's fields/rows feeds `applyBinding`. The 2.4 contract holds: a refill is `readDataSetTable -> applyBinding` with the mapping read back from the document. A block whose every bound (slotted) field is present in the fresh data re-resolves; any missing bound field leaves the block untouched (last-good data survives) and produces a diagnostic.

**Diagnostic problem-details / shape.** Per-block `BlockDiagnostic { blockId, blockType, label, state, drifts }` where `state` is `bound | drifted | unresolved` and each `FieldDrift` is `{ expected, closest, distance? }` (`closest: null` when no candidate). `state`: green when every bound field is present; amber (`drifted`) when some but not all are present (the present ones would rebind, the absent ones get a closest-match proposal); red (`unresolved`) when NO bound field is present (a foreign data set). The `remapField` service surfaces `remap` failures as RFC 9457 `AppError`s consistent with the schema error model: 404 `/problems/block-not-found`, 404 `/problems/binding-field-not-found`, 422 `/problems/unparseable-file` (a mapping that is incoherent on the fresh data). `BindingSummary { total, bound, drifted, unresolved, allGreen }` aggregates for the header ("N bindings - all green" / counts).

**Three component states wired (UX Flow B, `lib/ui/`).** `BindingChip` - green `Bound` (✓), amber `Drifted (n)` (▲, a button that toggles its DiagnosticPanel), red `Unresolved (n)` (✕); status never carried by colour alone (glyph + text label, NFR15). `BindingSummary` - a live region (`role="status" aria-live`) showing "N bindings - all green" or the by-state counts. `DiagnosticPanel` - the drift detail ("Expected `count` - closest match `counts`") with a per-drift one-click remap form (a snippet the editor fills with the `?/remap` action), and a manual field picker when there is no close match. The refill is orchestrated by a new editor-route `RefillPanel.svelte` (pick a fresh data set -> `?/rebind` -> chips + summary -> remap). All three components live in `lib/ui/` and are imported only by the workspace editor, so they never enter the reader closure - reader budget unchanged at 63.4 KB (< 200 KB).

**Workspace actions.** `?/rebind` (data set id -> `rebindReport`, returns diagnostics + summary + rebound ids) and `?/remap` (block/data-set/expected/available -> `remapField`, persists). Both author-realm under `workspaceGuard`; both target drafts (`updateReportDocument` refuses a published report with 409, so a refill on a published report is a clean conflict, not a silent skip).

**Tests: +34 (445 total).** `distance.test.ts` (13: Levenshtein identity/sub/ins/del/empty/case/symmetry/kitten-sitting, closestField exact-beats-near, nearest, null candidate, tie-break by index, strictly-closer-later). `diagnostics.test.ts` (12: green/amber/missing-with-candidate/empty-data-null-candidate/red/no-binding-skip/unslotted-skip, document all-green + mixed + empty aggregation). `rebind.test.ts` (9, mock-db pattern: FR14 rebinds all, renamed-field amber leaves block untouched, foreign-data red; remap persists+re-resolves, 404 unknown field, 404 unknown block).
