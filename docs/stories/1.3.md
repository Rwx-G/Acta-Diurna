# Story 1.3: Five-Minute Deployment

Status: Approved

## Story

As an operator,
I want to deploy the full stack with docker compose and env-only configuration,
So that a usable instance exists in under five minutes.

## Acceptance Criteria

**Given** a VM with Docker
**When** `cp .env.example .env` then `docker compose up -d`
**Then** the app starts, Drizzle migrations run automatically at boot, and `/healthz` reports app+db OK (FR34, NFR5, AR3)
**And** this story creates the Drizzle migration baseline (`drizzle-kit generate`) that the boot runner executes

**Given** a missing or invalid env variable
**When** the container starts
**Then** it fails fast with an explicit message naming the variable (AR9)

**Given** a running instance
**When** `git pull && docker compose up -d`
**Then** the upgrade completes with automatic migrations (NFR19)
**And** state survives via Postgres volume + uploads volume, restorable with `pg_dump` (FR37, NFR20)
**And** logs go to stdout only, JSON-formatted (pino), with no secret ever logged (NFR8/21, AR7)

## Tasks / Subtasks

- [ ] Drizzle setup: `drizzle.config.ts`, `src/lib/server/db/` (client.ts on node-postgres, schema.ts initially empty-but-wired, migrate.ts boot runner); `drizzle/` migrations dir committed
- [ ] Env validation: `src/lib/server/env.ts` - Zod-validated at boot, fail-fast naming the variable; `.env.example` (DATABASE_URL or PG parts, BASE_URL, SESSION_SECRET; SMTP vars declared but optional until Epic 3)
- [ ] pino logging: `src/lib/server/logger.ts`, request-id in hooks, JSON to stdout, redaction of secret-bearing keys
- [ ] `/healthz` endpoint (app + db round-trip status)
- [ ] Multi-stage `Dockerfile` (Node 22 alpine, non-root user, HEALTHCHECK, exec-form entrypoint running migrations then server) per `.claude/rules/docker.md`
- [ ] `docker-compose.yml`: app + postgres + named volumes (pgdata, uploads); `.dockerignore`
- [ ] Verify full cycle with Docker running: compose up from clean state, healthz OK, compose down/up state survival, missing-env failure message
- [ ] CI: add docker build job

## Dev Notes

- Authority: architecture D1/D2 (Drizzle 0.44 stable + node-postgres, JSONB later), D14 (adapter-node, alpine, healthz), AR9; `.claude/rules/docker.md` applies in full (pinned base image digest or version tag, .dockerignore, USER directive, cap drop where compose allows, OCI labels).
- Boot order: validate env -> run migrations -> start server. Migrations runner must be idempotent and crash loudly on failure.
- Story creates NO business tables (sessions/reports arrive with their stories) - the baseline migration may be empty or contain only infrastructure (e.g. nothing); what matters is the generate->apply pipeline working end to end.
- Docker is available on the host (verified): actually run the compose cycle, do not simulate.
- adapter-node serves on PORT/HOST envs; reverse-proxy headers handled by SvelteKit adapter options (trust X-Forwarded-*) - set ORIGIN/BASE_URL correctly.
