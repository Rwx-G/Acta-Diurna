# Story 1.3: Five-Minute Deployment

Status: Review

## Story

As an operator,
I want to deploy the full stack with docker compose and env-only configuration,
So that a usable instance exists in under five minutes.

## Acceptance Criteria

**Given** a VM with Docker
**When** `cp .env.example .env` then `docker compose up -d`
**Then** the app starts, Drizzle migrations run automatically at boot, and `/healthz` reports app+db OK (FR34, NFR5, AR3)
**And** this story creates the Drizzle migration baseline (`drizzle-kit generate`) that the boot runner executes

**Given** a missing or invalid env variable
**When** the container starts
**Then** it fails fast with an explicit message naming the variable (AR9)

**Given** a running instance
**When** `git pull && docker compose up -d`
**Then** the upgrade completes with automatic migrations (NFR19)
**And** state survives via Postgres volume + uploads volume, restorable with `pg_dump` (FR37, NFR20)
**And** logs go to stdout only, JSON-formatted (pino), with no secret ever logged (NFR8/21, AR7)

### Completion Notes

- **Boot-order choice**: SvelteKit `init` server hook (`ServerInit`) in `hooks.server.ts` running env validation then migrations - not a custom build/index.js wrapper, not an entrypoint script. adapter-node top-level-awaits `server.init()` before listening (verified in node_modules), so env -> migrate -> serve holds identically in `node build`, `vite preview` and `vite dev`; any throw aborts boot with a non-zero exit before the first request. Zero duplication between dev and container paths.
- **D1 deviation, flagged for arch reconciliation**: drizzle-orm is 0.45.2, not 0.44.x, because of GHSA-gpj5-g38j-94v9 (high). D1's intent (stable 0.x line, no 1.0 beta) is preserved; `docs/prd/architecture.md` still says 0.44 and should be reconciled by the architecture owner.
- **Env contract** (`src/lib/server/env.ts`): pure `parseEnv(raw)` (unit-tested) + cached `serverEnv()`. Empty strings are treated as absent (compose interpolation emits `""` for unset optionals). The error lists every offending variable with an actionable hint and never echoes values. SMTP_* are declared optional until Epic 3; invalid values still fail fast today.
- **Logger** (`src/lib/server/logger.ts`): reads LOG_LEVEL directly from process.env so it can report a broken environment before validation; the init hook re-applies the validated level. Redacts password/secret/token/authorization/cookie/sessionSecret/apiKey/smtpPass keys at nesting depths 0-2.
- **DATABASE_URL is assembled by compose** from POSTGRES_USER/PASSWORD/DB (single source for the password); `.env.example` documents the explicit override for non-compose runs. Container always listens on 3000; host port is mapped from PORT.
- **Image**: node:22-alpine digest-pinned (Node 22.22.3), multi-stage, runtime as uid 10001 with app files root-owned read-only and only /data/uploads writable, busybox-wget HEALTHCHECK on /healthz, exec-form `ENTRYPOINT ["node","build"]`, OCI labels (version 0.1.0 matching package.json; revision/created via build args). Compose app service: `no-new-privileges`, `cap_drop: [ALL]`, `read_only: true` + tmpfs /tmp - all verified working.
- **playwright.config.ts**: webServer block removed - `vite preview` now requires a live Postgres (boot migrations), and there are zero e2e specs. The first e2e story must reintroduce webServer together with a database fixture and env.
- **pnpm-workspace.yaml** added solely for `allowBuilds: esbuild` (pnpm 11 build-script approval).
- **Local-only, not committed** (`.claude/` is untracked by design): `secrets-fence.py` regex narrowed so exactly `.env.example` (the committed, .gitignore-whitelisted template) is writable; bare `.env` and every other `.env.*` variant remain blocked. Verified with a 10-case probe before use.
- **For stories 1.4/1.5**: read config via `serverEnv()` only; query via `getDb()`/`getPool()` from `$lib/server/db/client` (never a second Pool); new tables go in `src/lib/server/db/schema.ts` then `pnpm exec drizzle-kit generate` - boot applies them automatically; `event.locals.requestId` exists on every request for log correlation; pino redaction already covers secret-bearing keys but never log raw env or headers wholesale.
