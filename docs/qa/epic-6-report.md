# Epic 6 QA Report - Multi-Audience Reading & Governance

**Date:** 2026-06-14
**Author:** Romain G.
**Method:** per-story implementation, parallel auditors (security, attacker-mindset penetration, quality, architect, BMad gate), then a dedicated security + penetration pass over the whole epic before close. The epic touches the reader-facing render path, an author-private notes field, and an owner-scoped audit surface, so the speaker-notes privacy boundary, the audience visibility model, and the audit tenancy scope each took explicit attacker review. All work committed locally to `main`. ## Executive Summary

Epic 6 is complete: all 5 stories `Done`. One report now serves the whole room. Readers pick the depth they need - the level switcher renders summary / full / technical from one document, instantly, with near-zero added reader JS. Presenters present - an author-only presenter view runs a meeting from the same published document the readers received, with speaker notes, a next-section preview, a local timer, and a meeting mode that hides annexes from the flow. And authors govern - an owner-scoped access audit answers who read what and when, with a configurable retention window that closes the access-records retention deferred since Epic 3, plus a data-freshness caption so a reader never mistakes stale numbers for fresh ones, and a theme registry that lets different report series carry distinct, contrast-verified identities.

**Epic gate: PASS.** No Critical, High, Medium, or Low finding remained open at epic close. Every change is additive to schema v1 (the optional `notes` and `dataAsOf` fields, no version bump, every existing document still validates), renderer-pure (the audience switch and the data-as-of caption are static SSR, no `$lib/server` in the render path), AAA report content gated by axe-core, and within the reader JS budget (72.8 KB / 200 KB - the level switcher is the only added reader behaviour, a native radio group). No new dependency.

**The load-bearing distinction of the epic is what an audience tag IS and is NOT.** Audience tags are a presentation / reading-comfort filter, not a confidentiality boundary. Every audience level is server-rendered into the authorized reader's DOM and hidden only by CSS (`display: none` keyed off `data-level` / `data-audiences`). A reader at "summary" cannot see the "technical" blocks in the page, but those blocks ARE in the bytes shipped to that reader. This is correct for the feature (it keeps the switch instant, no round-trip, and keeps the reader budget flat) but it means confidential or per-reader-restricted content must never be gated behind an audience tag - the confidentiality boundary is the share itself (Epic 3), not the level. The one genuinely author-private field, section speaker notes, is NOT an audience tag and is stripped server-side before the document reaches any reader. This invariant is now recorded in the code at the audience helper and the `audiences` schema field so a future contributor cannot mistake the tag for an access control.

## Cross-Cutting Findings (multi-story signal)

- **Audience visibility is one isomorphic source of truth, and it is not an access control.** `isVisibleAtLevel` / `hasAudienceTags` / `audiencesAttr` (`src/lib/schema/audience.ts`) are the single predicate the reader switcher, the author per-level preview and the no-JS fallback all derive from, so they cannot drift. The mechanism is pure CSS: each block and section host carries a canonical-order `data-audiences` attribute, the report root carries `data-level`, and a scoped `:global([data-audiences]:not([data-audiences~='X']))` rule hides the non-matching elements with `display: none` (which removes them from layout AND the accessibility tree, so a screen reader at "summary" never reaches "technical" content). The not-confidentiality invariant is the corollary: all levels render into the DOM, so the tag is reading comfort, never a confidentiality boundary - now recorded in the code at both the helper and the schema field.
- **Speaker-notes privacy is triple-layered.** The author-only section `notes` field must never reach a reader, and three independent guarantees enforce it. (1) The reader view-model (`toReportView`) maps a section to a `SectionView` shape that has no `notes` field, so the rendered SSR HTML carries none. (2) The reader-served document is stripped: `getPublishedDocument` - the single chokepoint every reader path funnels through - runs `stripSpeakerNotes` over every section before the document leaves the server, so notes never ship in the hydration payload even though the HTML already hid them. (3) The presenter view, which IS allowed to read notes, is an owner-scoped workspace route that deliberately does NOT call `getPublishedDocument`; it loads the owner's own `publishedDocument` through the owner-scoped `getReport` and pairs notes onto presenter section pairs only, never onto the reader `SectionView`. The draft and the stored snapshot keep their notes; only the served copy is stripped.
- **The audit is owner-scoped with no existence oracle, and it closes a long-standing deferral.** `listAccessRecords` joins `access_records -> reports -> reader_identities` and ANDs the Epic 8 owner predicate onto `reports.owner_id`, so an author sees only accesses to their own reports; a cross-owner `?report=` filter is the same empty result as an unknown id, and a malformed filter id short-circuits to `[]` without touching the database (no postgres cast error, no 500, no oracle). Single mode is the no-op predicate (byte-identical query). Retention is the configurable counterpart: `ACCESS_RECORD_RETENTION_DAYS` is optional with NO default (unset = audit kept indefinitely, because an evidentiary trail must not silently age out by default), bounded `1..3650`, and `purgeAccessRecords` rides inside the existing boot sweep guarded OFF when unset. This is the deliberate retention the Epic 3 / 3.3 purge module explicitly deferred to 6.3 - the janitor no longer blindly skips access records, but it only deletes when an operator opts in.
- **Data-as-of is baked at bind time so the renderer stays pure.** The freshness instant lives only in the `data_sets` row, and the renderer is pure (no `$lib/server`, no DB). So `resolveDataAsOf` (explicit `data_as_of` else `injected_at`) is computed server-side and `applyBinding` stamps it onto `binding.dataAsOf` across all three write paths (bind, FR14 auto-rebind, FR15 remap); it persists in the document and rides into the published snapshot. `toReportView` stays untouched - the bound block already carries the instant, and the shared `DataAsOf` caption reads it straight off the validated document. The caption is formatted with a fixed locale + UTC (`Intl.DateTimeFormat('en-GB', ..., timeZone: 'UTC')`) so the SSR string is byte-identical on server and client (no hydration mismatch, no locale or timezone leak), and is OMITTED entirely when no usable timestamp exists (never a placeholder, never a misleading "unknown").
- **The theme registry is one source of truth and the fallback is exactly one place.** `BUILT_IN_THEMES` + `THEME_OPTIONS` (`lib/render/theme`) are the single registry the schema, the editor picker and the renderer share; a lockstep test asserts the palette / categorical / tone tables match the registry, so a half-skinned theme fails before render. `resolveTheme(slug)` is total - a known slug resolves to itself, anything else (absent, unknown, removed) resolves to `default` - so a stored document carrying a since-removed theme still validates (the schema stays soft, `theme: idSchema.optional()`, not an enum) and the reader never sees a broken theme; `themeFallbackWarning` surfaces an amber workspace advisory for an unknown slug. The new themes (Cool Aurora, Warm Meridian) are complete `--report-*` token blocks with hex twins so the contrast math runs without a browser; report content holds AAA (7:1) and decorative chrome holds the AA floor (4.5:1), asserted by the extended contrast tests.
- **Renderer purity and the reader budget held across the whole epic.** The audience switch is a CSS-data toggle plus one small native radio group; the data-as-of caption, the theme application, and the presenter stage add no reader-path JS. The presenter view is a hydrated WORKSPACE route, outside the `/r/[token]` reader closure the budget measures. Reader-path JS sat at 72.8 KB / 200 KB at epic close.

## Security Audit

The epic ran a dedicated security + attacker-mindset penetration pass after the five stories landed. **The result is clean: 0 Critical / 0 High / 0 Medium / 0 Low.** No remediation was required. The auditors stress-tested the surfaces the epic adds and found the following sound:

- **Speaker notes never reach a reader.** The triple layer holds - the reader view-model has no notes field, `getPublishedDocument` strips notes at the single reader chokepoint before the hydration payload is serialized, and the presenter route (the only path that reads notes) is owner-scoped and bypasses the stripping chokepoint by design. The auditors confirmed there is no reader path that serializes a `notes`-bearing section.
- **The owner-scoped audit is no oracle.** A cross-owner or unknown report / reader filter yields the same empty result, a malformed id short-circuits before any query (no cast error, no 500), and the report-filter dropdown only ever lists the author's own reports - so the audit view leaks nothing about another author's reports or readers. In single mode the predicate is a no-op and the query is byte-identical to an unscoped read.
- **No reader-path XSS on the new surfaces.** The data-as-of caption interpolates a formatted instant as escaped Svelte text (a malformed / script-like value formats to `null` and renders nothing), the audit view escapes every value (no raw HTML), and the audience-visibility attributes are serialized from a closed canonical enum order - no value reaches the DOM as markup.
- **Bounded retention with a conservative default.** `ACCESS_RECORD_RETENTION_DAYS` is optional, bounded `1..3650`, and has NO default, so a typo cannot delete fresh accesses (zero) or set an absurd window, and the evidentiary trail is never silently aged out unless an operator opts in. The purge is a pure function deleting on a strict `<` cutoff, wired into the existing guarded sweep.
- **The documented not-confidentiality invariant.** The auditors flagged that audience tags ship every level into the reader's DOM and must never be mistaken for an access boundary; the invariant is now recorded in the code (the audience helper and the `audiences` schema field) so the design intent cannot be silently violated by a future change that gates confidential content behind a tag.

## NFR Validation

- **Accessibility (NFR14).** The level switch uses `display: none`, which removes a level-excluded block from both layout and the accessibility tree, so a screen reader at one level never reaches another level's content; the switcher is a real labelled radio group (fieldset + legend), keyboard-operable, accepted by the existing axe gate. Both new themes hold AAA report content (body / muted / heading / accent-as-link, 7:1) and the AA decorative floor (4.5:1) on their own paper, machine-checked by the extended contrast tests; the `full` reader fixture now renders on `aurora` so a non-default theme is exercised under axe-core.
- **Performance / reader budget (NFR3).** Reader-path JS held at 72.8 KB / 200 KB at epic close. The audience switch is SSR-all-levels + a CSS toggle plus a tiny radio group; the data-as-of caption and the theme application are static SSR / CSS only; the presenter view is outside the measured reader closure.
- **Privacy / governance (FR24, FR38, NFR11).** The audit is owner-scoped both in the query and in the report-filter options, retention bounds how long reader-access rows live (GDPR data minimization), and the audit scope is kept minimal - who (reader email), which (report title), when (timestamp), nothing more.
- **Schema additivity / version tolerance (FR7).** The two new fields (`notes` on a section, `dataAsOf` on a binding) are optional and additive: a document without them validates and renders unchanged, no migration, no version bump - the JSON Schema artifact gains only the two optional properties. The presenter and the published renderer both run the stored snapshot through `validateStoredDocument` for N/N-1 tolerance.
- **Local-only presenter (FR29 non-goal).** All presenter state - current index, meeting mode, the elapsed timer - lives in one window. No websocket, no device sync, no real-time, honouring the explicit non-goal.
